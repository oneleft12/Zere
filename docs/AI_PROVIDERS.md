# Подключение ИИ: облачный ключ или локальная модель

Документ описывает выбор провайдера ИИ: свой API-ключ для облачной модели
и локальную модель (Ollama или другой OpenAI-совместимый сервер).
Контракт один на обе редакции — `docs/api/openapi.yaml` (раздел `ai`):

| Редакция | Модули | Маршруты |
|---|---|---|
| Python | `zere/ai/ai_settings.py`, `cloud_client.py`, `local_model.py`, `ai_service.py` | `zere/api/server.py` |
| C# | `ZERE.AI/AiSettings.cs`, `CloudClient.cs`, `LocalModelService.cs`, `AiService.cs`, `IAiClient.cs`, `AiError.cs` | `ZERE.App/Api/PanelServer.cs` |

Общая часть — интерфейс `IAiClient` (`generate/warmup`): `AIHandler` в обеих
редакциях работает через прокси выбора провайдера, поэтому смена провайдера
в панели применяется на лету, без перезапуска.

## 1. Как выбирается провайдер

Режим (`mode`) хранится в настройках и переключается в панели
(экран «Подключение ИИ»), API — `POST /api/ai/settings`:

| Режим | Что используется |
|---|---|
| `auto` (по умолчанию) | сначала облачный ключ; если ключа нет — локальная модель; если облако упало, а локальная модель доступна — ответ идёт локально |
| `cloud` | только облачный ключ |
| `local` | только локальная модель |

Приоритет при запросе в чат (`GET /api/chat/stream`):

1. есть рабочий облачный ключ → облачная модель;
2. ключа нет, но локальный сервер запущен и нужная модель загружена →
   локальная модель;
3. ни того, ни другого → в ответ приходит сообщение
   «Чтобы начать, введите API-ключ или установите локальную модель».

Состояние видно сразу при входе в панель: строка внизу
(`ИИ: облако` / `ИИ: локально` / `ИИ: не настроен`), карточка
«ИИ и модель» на дашборде и бейдж в чате.

## 2. Быстрый старт: свой API-ключ

1. Запустите ZERE (`python main.py`) — панель откроется автоматически.
2. Панель → «Подключение ИИ» → режим «Использовать свой API-ключ»
   (или оставьте «Авто»).
3. Выберите провайдера (OpenAI, DeepSeek, OpenRouter, Groq или «Свой
   OpenAI-совместимый сервер» — тогда укажите Base URL и модель).
4. Вставьте ключ → «Проверить ключ» (бэкенд делает рабочий запрос:
   `GET /models`, при необходимости минимальный `POST /chat/completions`).
5. «Сохранить» — ключ уходит на бэкенд в `config/ai.json`; в интерфейсе
   остаётся только маска `sk-...abcd`.

Нерабочий ключ не сохраняется: панель покажет «Неверный API-ключ»,
«На балансе нет средств», «Превышен лимит запросов» или «Модель
недоступна».

То же самое из командной строки (PowerShell/Bash, токен — в
`config/panel.token`):

```bash
TOKEN=$(cat config/panel.token)
BASE=http://127.0.0.1:8080

# 1. Проверить ключ, ничего не сохраняя
curl -s -X POST "$BASE/api/ai/key/test" \
  -H "X-ZERE-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"apiKey":"sk-...","cloudProvider":"openai","cloudBaseUrl":"https://api.openai.com/v1","cloudModel":"gpt-4o-mini"}'

# 2. Проверить и сохранить
curl -s -X POST "$BASE/api/ai/key" \
  -H "X-ZERE-Token: $TOKEN" -H "Content-Type: application/json" \
  -d '{"apiKey":"sk-...","cloudProvider":"deepseek","cloudBaseUrl":"https://api.deepseek.com/v1","cloudModel":"deepseek-chat"}'

# 3. Состояние подключения ИИ
curl -s "$BASE/api/ai" -H "X-ZERE-Token: $TOKEN"

# 4. Удалить ключ пользователя (ключ владельца из окружения не трогается)
curl -s -X DELETE "$BASE/api/ai/key" -H "X-ZERE-Token: $TOKEN"
```

## 3. Быстрый старт: локальная модель

1. Установите Ollama: <https://ollama.com/download>
   (`winget install Ollama.Ollama`).
2. Запустите сервер: `ollama serve` (обычно стартует сам после установки).
3. Скачайте лёгкую модель — кнопкой «Скачать модель» на экране
   «Подключение ИИ» (бэкенд вызывает `POST /api/pull` у Ollama и
   показывает прогресс) или вручную:

```bash
ollama pull qwen3.5:2b
```

Адрес по умолчанию — `http://127.0.0.1:11434/v1` (OpenAI-совместимый
`/v1` Ollama). Другой локальный сервер подключается просто сменой Base
URL: если он отвечает на `GET /models` и `POST /chat/completions`, ZERE
работает с ним так же.

Рекомендации по моделям (тяжёлые по умолчанию не предлагаются):

| Класс ПК | Модели |
|---|---|
| очень слабый | `qwen2.5:0.5b`, `qwen2.5:1.5b` |
| средний | `qwen2.5:3b` |
| по умолчанию в ZERE | `qwen3.5:2b` |

Если локальная модель не найдена, панель показывает блок
«Локальная модель не найдена» с шагами установки, кнопкой «Скачать
Ollama» и командой `ollama pull qwen3.5:2b` (копируется одной кнопкой).

Проверки локального сервера (`GET /api/ai/local`,
`POST /api/ai/local/test`):

- запущен ли сервер (native `/api/tags` для Ollama и `/models` для
  прочих совместимых серверов);
- какие модели доступны и загружена ли нужная;
- проходит ли минимальный тестовый запрос (`max_tokens: 1`).

```bash
# Состояние локальной модели (включая installHint, если её нет)
curl -s "$BASE/api/ai/local" -H "X-ZERE-Token: $TOKEN"

# Тестовый запрос к модели
curl -s -X POST "$BASE/api/ai/local/test" -H "X-ZERE-Token: $TOKEN" \
  -H "Content-Type: application/json" -d '{}'

# Загрузка модели с прогрессом (SSE: progress / done / error)
curl -sN "$BASE/api/ai/local/pull?model=qwen3.5:2b" -H "X-ZERE-Token: $TOKEN"
```

## 4. Примеры запросов к чату

Ответ приходит потоком SSE (события `token`, `done`, `error`):

```bash
# Облачная модель (ключ сохранён, режим auto/cloud)
curl -sN "$BASE/api/chat/stream?text=$(python3 -c 'import urllib.parse;print(urllib.parse.quote("привет"))')" \
  -H "X-ZERE-Token: $TOKEN"
# event: token
# data: {"text":"Привет! ..."}
# event: done
# data: {"answer":"Привет! ..."}
```

Провайдер выбирает бэкенд — в теле запроса его указывать не нужно.
Если ни ключа, ни локальной модели нет, в `done` придёт
`{"answer":"Чтобы начать, введите API-ключ или установите локальную модель"}`.

## 5. Переменные окружения

Ключ владельца/админа живёт только в окружении сервера и используется
только для его аккаунта: в `config/ai.json` он не попадает, из панели не
удаляется, обычному пользователю не показывается (в интерфейсе видна
маска и пометка «ключ владельца»).

| Переменная | Назначение | Пример |
|---|---|---|
| `ZERE_AI_MODE` | режим по умолчанию | `auto` |
| `ZERE_CLOUD_PROVIDER` | пресет провайдера | `deepseek` |
| `ZERE_CLOUD_BASE_URL` | Base URL облачного API | `https://api.deepseek.com/v1` |
| `ZERE_CLOUD_MODEL` | модель | `deepseek-chat` |
| `ZERE_CLOUD_API_KEY` | ключ владельца | `sk-...` |
| `ZERE_LOCAL_BASE_URL` | адрес локального сервера | `http://127.0.0.1:11434/v1` |
| `ZERE_LOCAL_MODEL` | локальная модель | `qwen3.5:2b` |

Пример файла — `.env.example` в корне репозитория.

## 6. Безопасность

- ключ используется только на бэкенде: в клиентский код и в ответы API
  он не попадает, в интерфейсе — маска `sk-...abcd` (поле ввода всегда
  пустое);
- файл `config/ai.json` создаётся с правами `0600` и внесён в
  `.gitignore` (вместе с `config/ai.json.tmp`);
- логи маскируются: `redact_secrets` в `zere/core/logging/log_service.py`
  вычищает `sk-...`, `Bearer ...`, `"apiKey": "..."` из сообщений
  `log_error`/`LogService`, поэтому ключ не попадёт даже в текст
  исключения HTTP-клиента;
- ключ каждого пользователя используется только для его запросов
  (файл настроек локальный); ключ владельца подставляется только когда у
  пользователя своего ключа нет.

## 7. Коды ошибок API

| Код | HTTP | Текст |
|---|---|---|
| `AI_KEY_INVALID` | 400 | Неверный API-ключ |
| `AI_NO_CREDITS` | 400 | На балансе нет средств |
| `AI_RATE_LIMIT` | 429 | Превышен лимит запросов |
| `AI_MODEL_UNAVAILABLE` | 400 | Модель недоступна |
| `AI_NETWORK` | 502 | Не удалось подключиться к облачному API — проверьте интернет и Base URL |
| `AI_PROVIDER_ERROR` | 502 | Облачный провайдер вернул ошибку |
| `AI_LOCAL_SERVER_DOWN` | 400 | Локальный сервер не запущен |
| `AI_LOCAL_MODEL_MISSING` | 400 | Локальная модель не загружена |
| `AI_PULL_UNSUPPORTED` | (SSE `error`) | Автозагрузка доступна только для Ollama |
| `VALIDATION_ERROR` | 400 | Тело запроса не прошло валидацию |

## 8. Запуск и проверка

```bash
# 1. Запуск ZERE (поднимет панель и откроет окно/браузер)
python main.py            # Python-редакция
ZERE.exe                  # C#-редакция (или dotnet run --project ZERE.App)

# 2. Тесты ИИ (без сети: облако и локальный сервер — фейковый HTTP)
python3 tests/test_ai_providers.py

# 3. Контрактные тесты панели (проверяют /api/ai* по openapi.yaml)
python3 tests/test_panel_api.py

# 4. Сборка панели (если правили фронтенд; panel/dist коммитится)
cd panel && npm run build

# 5. E2E-смоук (Playwright; сервер с фейками поднимается сам)
cd panel && npm run test:e2e
```

### Проверка C#-панели (контракт /api/ai)

```bash
# сборка (Windows-тулчейн)
dotnet build ZERE.slnx

# панель только с API, на свободном порту — без окна и без проверки голоса
dotnet run --project ZERE.App --no-build -- --panel --port 8091

# безопасные контрактные проверки /api/ai против неё
# (форма ответов, валидация, 401/405; ключи и модель пользователя не трогаются)
python tests/check_ai_contract_external.py 8091
```

То же для Python-редакции: запустите панель (`python main.py`) и выполните
`python tests/check_ai_contract_external.py 8080`.

Замечания:

- облачный ответ сейчас приходит одним событием `token` (без
  посимвольного стриминга) — как и прежде для локальной модели;
- Ollama перестала быть критической зависимостью, если настроен облачный
  ключ: ZERE стартует и отвечает через облако
  (`zere/core/dependencies/dependency_checker.py` — Python,
  `ZERE.Core/Dependencies/DependencyChecker.cs` — C#);
- тесты ИИ в `tests/test_panel_api.py` разделены: форма ответов, валидация
  и безопасность (401/405/400) проверяются и на настоящей панели любой
  редакции, а проверки с живым провайдером (`_require_inprocess_ai`) идут
  только на внутрипроцессном прогоне с фейковым HTTP — ключи и модель
  пользователя не трогаются.

## 9. Панель и редакции

Файлы панели (`panel/dist`) общие для Python- и C#-редакции: после
`git pull` новый интерфейс появляется сразу, а маршруты `/api/ai*` —
после перезапуска ZERE (и только если сборка содержит эту функцию).
Фронтенд один раз определяет возможности запущенного бэкенда
(`aiSupport()` в `panel/src/api.ts`) и не показывает ложных ошибок:

| Что запущено | Экран «Подключение ИИ» | Пункт меню | Статус-строка |
|---|---|---|---|
| Свежий запуск (обе редакции) | работает полностью | виден | `ИИ: облако/локально/не настроен` |
| Процесс старше `panel/dist` | «Нужен перезапуск ZERE» | виден | `ИИ: перезапустите ZERE` |
| Старая сборка без `/api/ai` | «В этой редакции настраивается только локальная модель» | скрыт | `ИИ: только локально` |

Что делать при сообщении «Нужен перезапуск ZERE»: закрыть ZERE и запустить
снова (`python main.py` или `ZERE.exe`) — панель подхватит новый код
сервера, и настройка ключа появится. Отдельно перезапускать браузер не
нужно.

В старой сборке (например, уже запущенный `ZERE.exe` прошлой версии)
дашборд показывает фактическое состояние локальной модели по `/api/health`
(Ollama запущена/не запущена и выбранная модель) и объясняет, что настройка
ключа появится после обновления и перезапуска.
