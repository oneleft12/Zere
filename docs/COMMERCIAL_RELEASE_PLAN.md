## 1. Резюме для руководителя

**ZERE функционально почти готов к коммерческому альфа-релизу, но юридически к продаже не готов вообще.** Три блокера высшего уровня:

1. **Нет LICENSE-файла** при заявленном MIT — формально исходники «все права защищены», покупатель/пользователь не получает никаких прав.
2. **Название ZERE — товарный знак Marvel Characters, Inc.** (рег. № 4737881; Marvel успешно оппонировала попытку BlackBerry зарегистрировать ZERE). Коммерческий выпуск под этим именем — прямой риск претензии. Нужен ребрендинг либо юридическое заключение о невозможности конфликта (в РФ/СНГ риск ниже, но при международной продаже — прямой).
3. **В git-истории навсегда зафиксированы биометрия голоса и пользовательская БД** (`voice/reference_output.mp3`, `voice/sample_pocket.wav`, 3× `processed_output_*.wav`, `zere.db`, суммарно 4.21 МБ). Публичный репозиторий с чужими голосовыми сэмплами — и репутационный, и (для коммерческого сбора персональных данных) регуляторный риск.

Техническая база при этом крепкая: CI (4 джобы), 95 зелёных тестов, рабочий Inno Setup-установщик с SHA-256, веб-панель с OpenAPI-контрактом и токеном, большинство P0-находок июньского аудита уже исправлены (история сохраняется, path traversal закрыт, TTL подтверждений, denylist критических процессов).

**Оценка готовности к продаже: ~60%.** Юридический блок — 20%, продукт — 75%, упаковка/дистрибуция — 65%, монетизация — 10%.

## 3. Юридический блок (критический путь)

### 3.1 Лицензирование собственного кода
- Добавить `LICENSE` (MIT или иная) **и** указать её в `.csproj`/`pyproject`.
- Выбрать модель: MIT (максимум распространения, минимум дохода с кода) **или** source-available коммерческая лицензия (proprietary + платная лицензия, код открыт для просмотра). Для коммерции рекомендуется **двойная лицензия**: сообщество → MIT, коммерческая перепродажа/встраивание → платный EULA.

### 3.2 Товарный знак «ZERE»
- **Факт:** Marvel Characters, Inc. владеет регистрацией ZERE (USPTO № 4737881) и оппонировала чужие заявки ([Justia TM](https://trademarks.justia.com/862/94/zere-86294162.html), [Goodmans: Marvel vs BlackBerry](https://www.goodmans.ca/insights/post/goodmans-ip-blog/marvel-and-nimbix-oppose-blackberry-zere-trademark)).
- **Варианты:**
  1. **Ребрендинг** (рекомендуется): новое имя до коммерческого анонса — дешевле, чем потом. Внутри проекта имя ассистента может оставаться «Джарвис» как конфигурируемый wake word (пользовательское упоминание пользователем — иное дело, но продуктовое имя и логотип — нет).
  2. Продажа только в РФ/СНГ без упоминания Marvel-ассоциаций — снижает, но не снимает риск при публикации на международных площадках.
  3. Юридическое заключение — только при готовности к судебным издержкам.
- Переименование затронет: `AppId` Inno Setup, репозиторий, README/AGENTS, панель, имена процессов, `%LOCALAPPDATA%` пути.

### 3.3 Лицензии зависимостей (обязательны к списку THIRD-PARTY-NOTICES)

| Компонент | Лицензия | Коммерция |

### 3.4 Персональные данные
- Продукт собирает: голос (биометрия), текстовую историю, факты о пользователе. Всё локально — это **главный маркетинговый аргумент**, но нужен Privacy Policy (что собирается, где хранится, что не уходит в сеть), и — при продаже в РФ — учёт 152-ФЗ (оператором становится покупатель? нет — обработка на устройстве оператором не признаётся, но формулировки лучше подтвердить юристом), при продаже в EU — GDPR-декларация (local-only, no telemetry).
- Решение по телеметрии: **никакой без согласия**; опциональная анонимная статистика с opt-in.

## 4. Технический блок перед релизом

### 4.1 Обязательно (release blockers)
1. **Одна основная редакция.** Две реализации (C# + Python) удваивают стоимость поддержки и дают дрейф (уже зафиксирован: C# читает `ttsEngine`, Python — нет; Python не имеет PocketTTS). Решение: либо Python-версия как основная (текущая ветка, CI), C# — legacy; либо наоборот. Держать обе в коммерции — нельзя.
2. **Unit-тесты ядра:** роутеры команд, FileManager (граничные случаи путей), репозитории, подтверждения опасных действий. Минимум — критичные для безопасности пути.
3. **Переаудит безопасности** после серии исправлений (проверить статус P1-10, P1-11, P1-12 из аудита 2026-09-23) + pin зависимостей (сейчас `requirements.txt` — только нижние границы, lock нет).
4. **Очистка git-истории** (`git filter-repo`): `zere.db`, все `.wav`/`.mp3`. Репозиторий маленький (7 МБ) — сделать **до** публичного привлечения внимания.
5. **Очистка рабочего дерева от рантайм-артефактов** и расширение `.gitignore`.

### 4.2 Желательно до публичного анонса
6. Код-подпись: `signtool` + сертификат (EV ~$300–500/год, OV дешевле; **или** публикация MSIX в Microsoft Store — подпись бесплатна ([Microsoft docs](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)). Без подписи SmartScreen покажет «Неизвестный издатель» — конверсия установок падает кратно.
7. Автообновление (минимум — проверка GitHub Releases + ссылка; максимум — sparkle-подобный механизм).
8. Версионирование: git-теги `v1.7.0`, живой `CHANGELOG.md`, семантические версии, единый источник версии (сейчас `config.json`, `Zere.iss` расходятся вручную).
9. Дефект-барьер: smoke-тест на реальном Windows-ПК (голос, kill, shutdown, установка/удаление) — CI такого не даёт.
10. Инсталлятор: убрать возможные shell-инъекции при распаковке (P1-12), проверить ещё раз.

### 4.3 Бизнес-функции (для платной версии)
11. Механизм лицензии: ключ активации (offline-код или online-check с fallback), гейтинг Pro-функций.
12. Trial/Free-версия: что входит (см. §6).

## 6. Модель монетизации (рекомендация)

Продукт — локальный, без облачных издержек, из чего следует простая воронка:

| Тариф | Цена (ориентир) | Содержимое |
|---|---|---|
| **Free** | $0 | консоль + базовые команды, текстовый ввод, 1 личность, память (лимит), без голоса или с Piper |
| **Pro (one-time)** | $19–39 | голос (STT/TTS, клонирование), все личности, веб-панель, расширенная память, приоритетные обновления |
| **Pro + Support** | $49–99 | то же + приоритетная поддержка, ранние сборки |
| Будущее | — | Marketplace плагинов (комиссия 20–30%), корпоративные лицензии |

Альтернативы, которые стоит рассматривать параллельно:
- **Donations + open core** (MIT-база, Pro-модули) — если цель не выручка, а аудитория.
- **B2B-укрупнение**: «ассистент, который не утекает в облако» — сильный аргумент для юрлиц с запретом на облачные LLM; юрлица платят ×5–10.

Дифференциация против конкурентов (Jan, LM Studio — бесплатные, но без управления ПК и голоса; облачные ассистенты — не локальные): **«единственный локальный голосовой ассистент, который управляет Windows и ничего не отправляет наружу»** — это и есть позиционирование.
