# Конспектор ZERE: материал → конспект в Obsidian

**Что это:** ZERE сам пишет конспект по материалу — локальному файлу (`.md`,
`.txt`, `.pdf`), статье по ссылке или тексту, присланному в чат, — и сохраняет
его заметкой в хранилище Obsidian: с frontmatter, тегами и разделом дел.

**Дата:** 14 октября 2026. **Редакция:** Python. Паритет C# — не сделан, см. §9.

---

## 1. Зачем это, а не «отправить текст в чат»

Ключевое ограничение проекта: `num_ctx = 2048` в `OllamaClient`
(`zere/ai/ollama_client.py`, анализ S5). Это окно **всей** генерации — system
промпт, инструкция, материал и ответ. Часовая лекция — это ~40 000 символов,
то есть примерно 16 000 токенов: такая простыня в окно не входит, и Ollama
молча отбрасывает начало. Пользователь получил бы «конспект» последних двух
минут и не узнал бы об этом.

Поэтому конспектор не «улучшает промпт», а делает конвейер:

```
источник → текст → части → конспект по каждой части → сводка → заметка
                     (map)                            (reduce)
```

Обе стадии укладываются в окно модели: часть — до 2400 символов (≈960
токенов), ответ по части — до 400 токенов; сводка получает уже сжатые заметки
частей.

| Компонент | Где | Назначение |
|---|---|---|
| Настройки | `zere/core/conspect/config.py`, `config/conspect.json` | хранилище, папка, теги, потолки |
| Чанкование | `zere/core/conspect/chunking.py` | части по абзацам и предложениям, с перекрытием |
| Извлечение текста | `zere/core/conspect/text.py` | файл, PDF, страница по URL |
| Контракт заметки | `zere/core/conspect/contract.py` | промпты, разделы, frontmatter, сборка Markdown |
| Запись в хранилище | `zere/core/conspect/vault.py` | безопасный путь, атомарная запись, список конспектов |
| Оркестратор | `zere/core/conspect/summarizer.py` | map-reduce, сбои частей, отказы |
| Мост к ИИ | `zere/core/conspect/ai_bridge.py` | «готова ли модель», подпись модели |
| Чат и голос | `zere/core/handlers/conspect_handler.py` | «законспектируй …» в конвейере |
| Длинные материалы | `zere/core/conspect/cli.py` | `python -m zere.core.conspect …` |

## 2. Быстрый старт

1. **Хранилище.** Конспекты идут туда же, куда и заметки: путь берётся из
   `config/mcp.json` (`servers.obsidian.env.SEEKSTONE_VAULT`). Если MCP-плагин
   заметок уже настроен — делать ничего не нужно.

2. **Свой конфиг (необязательно):**

   ```powershell
   copy config\conspect.example.json config\conspect.json
   ```

   ```json
   {
     "vault": "C:\\Users\\Вы\\Documents\\ZERE Notes",
     "folder": "Конспекты",
     "tags": ["конспект"],
     "maxChunks": 40,
     "interactiveMaxChars": 20000
   }
   ```

   `config/conspect.json` в `.gitignore` (в нём локальный путь). Если файла
   нет — работают значения по умолчанию, а хранилище всё равно берётся из
   `config/mcp.json`.

3. **ИИ.** Конспект делает та же модель, что отвечает в чате: облачный ключ
   или локальная Ollama (`docs/AI_PROVIDERS.md`). Ничего дополнительно
   подключать не нужно.

4. **Проверка в чате:**

   ```
   законспектируй C:\Лекции\лекция.md
   конспекты
   ```

## 3. Команды

### В чате и голосом (обработчик конвейера)

| Команда | Что делает |
|---|---|
| `законспектируй C:\путь\лекция.md` | конспект локального файла (`.md`, `.txt`, `.pdf` и др.) |
| `законспектируй https://example.com/article` | конспект статьи: страница скачивается и разбирается |
| `законспектируй: <текст>` | материал прямо в сообщении (от 300 символов) |
| `сделай конспект из лекция.md` · `конспект файла лекция.md` | те же команды другими словами |
| `конспекты` · `покажи конспекты` | последние сохранённые конспекты |
| `законспектируй` (без источника) | подсказка по формам команд |

Ответ короткий и озвучиваемый: «Готово. Конспект: Конспекты/2026-10/…md.
Частей материала: 4, время: 96 с.»

### Из консоли (длинные материалы)

```powershell
python -m zere.core.conspect лекция.md
python -m zere.core.conspect https://example.com/article --tags нейросети,обучение
python -m zere.core.conspect book.pdf --folder Книги --max-chunks 60
python -m zere.core.conspect лекция.md --dry-run     # показать, не записывать
python -m zere.core.conspect --list                  # те же конспекты, что в чате
python -m zere.core.conspect --json лекция.md        # машинный отчёт об операции
```

CLI печатает прогресс по частям (`[3/12] конспектирую часть…`) и не
ограничен потолком чата. Коды возврата: `0` — конспект сделан, `1` — отказ с
причиной.

## 4. Что попадает в заметку

```markdown
---
title: "Конспект: Лекция про LoRA"
source: https://example.com/lora
sourceType: url
created: 2026-10-14
parts: 4
tags:
  - конспект
  - обучение
---

# Конспект: Лекция про LoRA

> Ссылка: https://example.com/lora

## Суть
…
## Ключевые тезисы
…
## Термины
…
## Action items
…
## Открытые вопросы
…

---
_Конспект ZERE · Частей материала: 4 из 4; модель: локально · t-tech/T-lite-it-2.1; время: 96 с_
```

Разделы и их порядок — часть контракта (`contract.py`): их правит тот, кто
«шлифует» формат под себя, не трогая чанкование и запись.

**Имя файла** — из заголовка источника (`Конспект-Лекция-про-LoRA.md`), папка
— `folder/YYYY-MM/`. Кириллица в имени сохраняется: Obsidian ищет и сортирует
такие файлы нормально.

**Существующая заметка не перезаписывается:** при совпадении имени добавляется
`-2`, `-3` и так далее. Конспект за прошлый месяц дороже нового.

**Сноска честная.** Если модель не ответила по части материала или сводка не
удалась, это видно в заметке («частей без ответа модели: 2», «материал был
обрезан по потолку частей»), а не растворяется в тексте.

## 5. Настройки `config/conspect.json`

| Поле | Смысл | По умолчанию |
|---|---|---|
| `enabled` | выключает конспектор целиком (`false` — обработчик инертен) | `true` |
| `vault` | путь к хранилищу Obsidian; пусто — из `config/mcp.json` | `""` |
| `folder` | папка конспектов внутри хранилища | `Конспекты` |
| `tags` | теги заметки (во frontmatter). Строка `"конспект, обучение"` тоже принимается | `["конспект"]` |
| `subfolderByMonth` | раскладывать по подпапкам `YYYY-MM` | `true` |
| `writePaths` | подпапки, куда вообще разрешено писать; пусто — только `folder` | `[]` |
| `chunkChars` | размер части материала в символах | `2400` |
| `chunkOverlap` | перекрытие соседних частей (мысль на стыке не теряется) | `200` |
| `maxChunks` | потолок числа частей: это число вызовов модели | `40` |
| `interactiveMaxChars` | потолок материала **для чата** (панель ждёт ответ синхронно) | `20000` |
| `maxSourceChars` | потолок входного материала | `400000` |
| `maxDownloadChars` | потолок скачиваемой страницы (HTML) | `2000000` |
| `timeoutSeconds` | таймаут загрузки страницы | `60` |
| `temperature` | температура генерации конспекта | `0.3` |
| `maxTokensPerChunk` | длина ответа по одной части | `400` |
| `maxTokensSummary` | длина ответа сводки (это и есть конспект) | `900` |

Читаются и snake_case-имена (`chunk_chars`) — как в `config/ai.json` и
`config/mcp.json`: у проекта две редакции, и файл настроек не должен молча
сбрасывать чужие ключи. Битый JSON не ломает конспектор: причина уходит в
журнал, работа продолжается на умолчаниях.

**Почему `chunkChars` именно 2400.** При `num_ctx = 2048` и русском тексте
(~2.5 символа на токен) часть — это ~960 токенов, плюс инструкция промпта и
ответ до 400 токенов: помещается с запасом. Увеличивать `chunkChars` без
увеличения окна модели нельзя — часть начнёт обрезаться молча (в конспекте
появится дыра).

## 6. Как это работает

### Чанкование (`chunking.py`)

Текст режется по границам абзацев; абзац крупнее части — по границам
предложений; слишком длинное предложение — жёстко по символам. Соседние части
перекрываются (`chunkOverlap`), поэтому мысль на стыке попадает хотя бы в одну
часть. Оценка токенов (`estimate_tokens`) нарочно пессимистичная: лучше сделать
на часть больше, чем упереться в окно.

### Два прохода (`summarizer.py`)

1. **map:** каждая часть → сжатые заметки (`maxTokensPerChunk`);
2. **reduce:** заметки частей → конспект по контракту (`maxTokensSummary`).

Одна часть — сводка не нужна: ответ по части уже конспект (экономит вызов
модели). **Сбой одной части не отменяет конспект** — часть помечается в сноске
заметки. **Сбой сводки не теряет работу** — в заметку ложатся заметки частей.
Отказ возможен только тогда, когда модель не ответила ни разу.

Отдельная тонкость: `AiService.generate` при отсутствии провайдера **не
бросает исключение**, а возвращает текст («Введите API-ключ…»). Без проверки
этот текст уехал бы в заметку как конспект. Поэтому есть `preflight` (проверка
до работы) и распознавание таких ответов по тексту (`_looks_like_error`).

### Извлечение текста (`text.py`)

- **Файлы** читаются встроенно: текстовые форматы — как есть, HTML —
  через `HTMLParser` (скрипты, стили, навигация и подвал отбрасываются),
  PDF — через необязательный `pypdf`. Бинарный файл и пустой файл
  распознаются и объясняются словами.
- **Страницы** забираются `requests` (уже зависимость проекта). Приватные
  адреса (`127.0.0.1`, `192.168.*`, `localhost`, имена без точки) по умолчанию
  **запрещены**: иначе ссылка из чужого текста превратилась бы в запрос к
  локальным службам машины. Разрешить — только `--allow-private` в CLI.
- **Определение «это URL или путь»** сделано вручную, потому что `urlparse`
  считает `C:\лекция.md` адресом с «хостом» `c:`, а `лекция.md` — доменом `.md`
  (такое расширение у Молдовы тоже есть). Правила и таблица случаев — в
  `tests/test_conspect.py::test_is_url_table`.

### Запись (`vault.py`)

Заметка пишется **напрямую в файлы хранилища**, а не через MCP-плагин заметок:

1. сторонний процесс (Node + `seekstone`) не нужен в критическом пути: его
   сбой превратил бы готовый конспект в потерянный, и он живёт только внутри
   сессии ZERE;
2. меньше прав — меньше риска: писатель умеет писать только в папку конспектов
   (или в `writePaths`), путь проверяется на абсолютность, `..`, запрещённые
   символы Windows и зарезервированные имена, а запись идёт через временный
   файл и `os.replace` (обрыв не оставит половину заметки).

Поиск и чтение заметок остаются за MCP-плагином (`заметки найди …`,
`docs/MCP_PLUGINS.md`) — дублировать индекс хранилища здесь незачем.

## 7. Потолок чата и почему есть CLI

Конвейер ZERE синхронный: `PluginCommandHandler`, `ConspectHandler` и
`AIHandler` вызываются внутри обработки сообщения (`/api/chat/stream` отдаёт
ответ одним куском, а не по мере генерации). Значит, время конспекта — это
время ожидания панели.

На CPU конспект одной части 8B-моделью — это десятки секунд. Материал на
20 000 символов — это ~8 частей, то есть минуты. Поэтому у чата есть потолок
`interactiveMaxChars` (по умолчанию 20 000 символов): больший материал не
берётся в работу, а возвращается подсказка с готовой командой CLI. Это честнее
«зависшей» панели: пользователь сразу знает, что делать.

**Что дальше (не сделано):** фоновая очередь с уведомлением. Тогда конспект
часовой лекции можно будет запускать из чата, а результат — забирать
командой «конспекты» или уведомлением панели. Сегодня это осознанно
отложено: половина очереди без уведомления хуже явного CLI.

## 8. Тесты

```powershell
python -m pytest tests/test_conspect.py tests/test_conspect_handler.py -q
```

- `tests/test_conspect.py` — настройки (camelCase/snake_case, битый JSON,
  хранилище из `config/mcp.json`), чанкование (потолок размера, перекрытие,
  предложения с `3.5` и датами), извлечение текста (HTML без скриптов и
  навигации, файл, PDF без парсера, страница через фейковый HTTP, отказ на
  приватный адрес), контракт и frontmatter, писатель (запрет `..` и абсолютных
  путей, `writePaths`, «первая заметка не перезаписывается», отсутствие
  временных файлов), оркестратор (map-reduce, сбой части, сбой сводки, отказ
  при отсутствии модели, проверка хранилища **до** работы модели, dry-run), CLI.
- `tests/test_conspect_handler.py` — разбор фраз (и, главное, что команды
  конспектора **не отбирают** чужие: «заметки найди …», «прочитай файл …»),
  потолок чата, список конспектов, сбои (нет файла, нет модели, нет хранилища,
  исключение модели).

Сети и живой Ollama тесты не требуют: HTTP — `tests/fake_http.py`, модель —
фейк в тесте, хранилище — временный каталог.

## 9. Ограничения и что дальше

1. **Паритета C# нет.** Конспектор реализован только в Python-редакции
   (как и MCP-плагины). Для паритета нужны: `ConspectHandler.cs`,
   чанкование, писатель заметок и тот же CLI.
2. **Фоновой очереди нет** — см. §7.
3. **Конспект синхронный, один за раз.** Два параллельных конспекта подождут
   друг друга: модель на CPU одна.
4. **YouTube и Telegram не подключены.** Субтитры YouTube — отдельный
   источник (нужен разбор ссылки и сети), Telegram — MTProto и личный аккаунт;
   оба сознательно оставлены на потом, как и запись созвонов. Для созвонов
   полезно помнить: в ZERE уже есть запись звука и офлайн-STT GigaAM
   (`ZERE.Voice`), то есть «законспектируй последний час» технически ближе к
   локальной записи, чем к API Zoom/Meet.
5. **PDF без OCR.** Скан без текстового слоя не читается: нужен OCR
   (отдельная задача). `pypdf` читает только текстовый слой.
6. **Никакого RAG нет и он не нужен для «что я конспектировал».**
   Конспекты — обычные заметки хранилища: их ищет MCP-плагин заметок
   (`заметки найди …`), а даты и теги видны во frontmatter. Векторная база
   (`sqlite-vec` + эмбеддинги Ollama) понадобится только для поиска по
   материалам вне Obsidian или на больших объёмах.
7. **Качество зависит от модели.** Локальная 8B на русском даёт нормальный
   конспект лекции, но длинные материалы и сложные статьи лучше удаются
   облачному ключу. Обратная сторона: с облачным ключом материал уходит
   наружу — конспектор не решает эту дилемму, а показывает её.
8. **Озвучка ответа — короткая.** В заметку может уйти длинный конспект, но в
   чат возвращается одна строка (§3): TTS читает ответ целиком, а не заметку.
