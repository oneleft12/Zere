# ZERE как приложение (`zere.exe`)

**Дата:** 2026-10-29
**Статус:** сделано — приложение открывается одним окном; консольный режим
остался только для отладки.

---

## 1. Задача

До этого ZERE запускался как консольный процесс: чёрное окно с логом и
вкладка браузера с панелью. Пользователь просил «как приложение, а не
фронтенд и бекенд консоль», то есть `zere.exe`: двойной клик — окно, и
ничего лишнего.

Что нужно было сохранить:

- **одну панель** (`panel/dist`) — без второй кодовой базы UI;
- **один API-контракт** (`docs/api/openapi.yaml`) и loopback+токен;
- **обе редакции** (Python и C#) — десктоп-оболочка не должна ломать ни одну;
- **все возможности** Python-редакции: конспектор, MCP-плагины, рисование,
  роутер Jev, обновления.

## 2. Решение

```
zere.exe (C# 5, .NET Framework)          ← видимая точка входа, без консоли
   │  находит .venv\Scripts\pythonw.exe
   │  запускает main.py --desktop (окно процесса скрыто)
   ▼
main.py --desktop
   ├── ZereEngine, память, голос — как в консоли
   ├── PanelServer  http://127.0.0.1:8080   (loopback + X-ZERE-Token)
   └── pywebview / WebView2 → окно "ZERE" с panel/dist
```

Почему так, а не Electron/Tauri/нативный перепись:

| Вариант | Стоимость | Паритет UI | Итог |
|---|---|---|---|
| **pywebview + WebView2** | ~день | 100% (та же SPA) | ✅ выбрано |
| Electron/Tauri | недели | 100%, но новый рантайм | ❌ третий стек |
| Нативный WPF/Avalonia | недели | двойная поддержка экранов | ❌ дрейф |
| Только ярлык на pythonw | часы | окна нет | ❌ нет окна в панели задач |

Оценка вариантов подробнее — `docs/DESKTOP_SHELL_EVALUATION.md` (вариант B),
исходный план — `docs/GUI_DEVELOPMENT_PLAN.md` (этап 6).

## 3. Режимы запуска

| Команда | Что происходит |
|---|---|
| `zere.exe` (ярлык, двойной клик) | приложение: окно, консоли нет, панель в окне |
| `zere.exe --console` | отладка: запускает Python в консоли, как раньше |
| `python main.py --desktop` | то же приложение без лаунчера |
| `python main.py` | консольный режим: команды текстом, панель в браузере |
| `python main.py --port 8081 --desktop` | второе окно на другом порту (отладка) |

`--desktop`, `--app`, `--gui` — синонимы.

## 4. Лаунчер `zere.exe`

Исходник — `zere/desktop/launcher/ZereLauncher.cs` (C# 5: системный
`csc.exe` из .NET Framework 4.x не знает интерполяции строк). Собирается
`scripts/build-zere-exe.ps1`; установщик вызывает её, если `zere.exe` нет.
Готовый exe (≈60 КБ, с иконкой) коммитится в корень — после `git pull`
ярлык работает без сборки.

Что делает:

1. **Ищет корень ZERE** по `main.py` вверх от себя (допускается запуск из
   `bin\`).
2. **Один экземпляр** — `Local\ZERE.Desktop.Launcher`. Повторный запуск
   находит окно `ZERE` (`FindWindow`), восстанавливает и выводит вперёд;
   второй сервер не поднимается.
3. **Находит Python**: `.venv\Scripts\pythonw.exe` → `pythonw.exe` в `PATH`.
   Нет ни того, ни другого — окно с подсказкой про `installer\Install-Zere.bat`.
4. **Запускает `main.py --desktop`** без окна процесса (`CreateNoWindow`),
   стандартный вывод и ошибки забирает себе и пишет в `logs\desktop.log`
   (`PYTHONIOENCODING=utf-8`, `PYTHONUNBUFFERED=1`).
5. **Следит за стартом**: если процесс умер за первые 7 секунд, показывает
   окно с кодом и последними строками журнала. Коды `2` (окно не открылось)
   и `3` (панель занята) Python уже показал сам — второй диалог не выводится.
6. **Ждёт закрытия окна** и выходит с тем же кодом, отпуская мьютекс.

`--console` (или `--cli`) не добавляет `--desktop` и не перехватывает вывод —
получается прежняя консоль Python со всем текстом на экране.

## 5. Окно (`zere/desktop/window.py`)

- `run_window(url, …)` — `webview.create_window` + `webview.start`; обязателен
  главный поток (pywebview ставит обработчик SIGINT, из фонового потока —
  `ValueError`).
- `private_mode=False`, профиль — `data/webview/`: тема и язык панели
  (`localStorage`) переживают перезапуск. Раньше pywebview по умолчанию
  стирал их на каждом закрытии.
- `text_select=True` — текст в чате можно выделять.
- `on_ready` — pywebview зовёт его после старта GUI; там поднимается голос и
  прогрев модели, чтобы окно появлялось сразу, а не через секунды.
- `PanelWindowHost` — окно для консольного режима (команда «панель»):
  фоновый поток + откат в браузер, если pywebview так не может.

## 6. Нет консоли — нет stdout

`zere.exe` запускает `pythonw.exe`: у процесса `sys.stdout is None` и
`sys.stderr is None`. Это не мелочь: `print()` молча теряется, а
`sys.stdout.flush()` падает с `AttributeError` — то есть старт ZERE
обрывался бы на первой же записи. Поэтому `zere/desktop/stdio.py`
подменяет отсутствующие потоки файлом `logs/desktop.log` **до** первого
вывода. Когда консоль есть (запуск из терминала), подмена не включается.

Журналы: `logs/desktop.log` — старт приложения и вывод Python;
`logs/zere_*.log` — журнал ZERE (как и раньше); `logs/errors.log` — ошибки.

## 7. Ошибки старта и коды возврата

| Код | Значение | Кто показывает диалог |
|---|---|---|
| 0 | окно закрыто пользователем | — |
| 2 | окно не открылось (нет WebView2/pywebview) | Python: «Панель открыта в браузере» |
| 3 | порт 8080 занят — вероятно, ZERE уже запущен | Python: «Закройте его окно…» |
| прочие | сбой | лаунчер: код + конец `logs/desktop.log` |

Если окно не открылось, панель **временно** открывается в браузере, а
модальное сообщение объясняет, как вернуть окно; после «ОК» процесс
завершается. Это честный откат, а не тихая подмена.

## 8. Зависимости

- **pywebview** (`requirements.txt`, только Windows) — окно. Импорт ленивый:
  без пакета ZERE работает, панель открывается в браузере.
- **WebView2 Runtime** — есть в Windows 11 и вместе с Edge в Windows 10.
  Установщик проверяет его и предупреждает, если нет.
- **.NET Framework 4.x** — только для `zere.exe`; он предустановлен в
  Windows 10/11, отдельного рантайма не требует.
- **Smart App Control (Windows 11)** — блокирует *новые* неподписанные exe:
  только что собранный `zere.exe` запускается с «заблокирован политикой
  Device Guard вашей организации». Коммитнутая сборка может быть разрешена
  по репутации конкретного хэша, но пересборка получает новый хэш и блок.
  Поэтому установщик проверяет `VerifiedAndReputablePolicyState` и в этом
  режиме делает ярлыки на подписанный `pythonw.exe` с аргументами
  `main.py --desktop` (окно то же, консоли нет); `ZERE.bat` делает так же.
  Совсем отключить SAC можно только в Windows Security (обратно без
  переустановки Windows не включается) — решение пользователя.
- **onnxruntime из System32 (Windows 11)** — `C:\Windows\System32\onnxruntime.dll`
  (1.17.1, Windows ML) перехватывает загрузку у sherpa-onnx (собран против
  1.28): предзагрузка GigaAM падала с access violation, и приложение
  замолкало через ~10 секунд после старта. `preload_bundled_onnxruntime()`
  грузит ORT из пакета sherpa по полному пути до `import sherpa_onnx` и до
  `import onnxruntime` (KWS); регрессия — `tests/test_onnx_preload.py`.

## 9. Сборка

```powershell
# иконка (нужен Pillow): assets\zere.ico
python scripts\make_icon.py

# zere.exe (системный csc, без dotnet SDK)
powershell -ExecutionPolicy Bypass -File scripts\build-zere-exe.ps1
```

Установщик (`installer\install.ps1`) собирает `zere.exe`, если его нет,
ставит `pywebview` из `requirements.txt`, проверяет WebView2 и создаёт
ярлыки на `zere.exe` (а не на `ZERE.bat`); при включённом Smart App Control —
на `pythonw.exe` с аргументами `main.py --desktop`.

## 10. Автозапуск вместе с Windows

Экран панели «Настройки» → карточка «Запуск вместе с Windows»: переключатель
применяется сразу (кнопка «Сохранить» не нужна) и не пишет `config.json` —
источник истины реестр.

- Запись: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение
  `ZERE` — только текущий пользователь, права администратора не нужны.
  Видна в «Диспетчере задач» → «Автозагрузка».
- Команда: `"<папка ZERE>\zere.exe"`; если лаунчера нет —
  `"<папка>\.venv\Scripts\pythonw.exe" "<папка>\main.py" --desktop`
  (то же окно без консоли). Пути с пробелами экранируются.
- Отключение удаляет значение; повторное включение перезаписывает запись
  путём текущей установки (после переноса папки — `outdated=true` в API).
- Деинсталлятор (`installer/uninstall.ps1`) удаляет запись `ZERE`, чтобы
  после удаления приложения Windows не пыталась его запускать.
- API: `GET|POST /api/autostart` (`{enabled: boolean}`); на не-Windows —
  `supported=false`, включение → 409 `AUTOSTART_UNSUPPORTED`.
- Код: `zere/core/autostart.py`; тесты — `tests/test_autostart.py` и
  контрактные в `tests/test_panel_api.py`.

## 11. Проверка

- `python tests/test_desktop.py` — stdio pythonw, разбор `--desktop`/`--port`,
  сценарий «панель → окно → остановка» на фейках, коды 2/3, артефакты.
- `python main.py --desktop` — живая проверка окна.
- `ZERE.bat` — проверка запасного пути: при включённом SAC он запускает
  `pythonw.exe main.py --desktop` (подписанный бинарник, блокировки нет).
- `zere.exe` — проверка лаунчера, единственного экземпляра и журнала.
- `GET/POST /api/autostart` и переключатель в «Настройках» — проверка
  записи в `HKCU\...\Run` (включить, отключить, посмотреть Диспетчер задач).

## 12. Ограничения

- Трея нет: закрытие окна завершает ZERE (как обычное приложение). Если
  понадобится «свернуть в трей» — это отдельная задача (pystray/иконка).
- pywebview не умеет несколько окон в одном процессе — второе окно (другой
  порт) запускается отдельным `zere.exe --port …` только для отладки.
- Окно показывает ту же панель: всё, чего нет в панели (консольные
  «настройки», «записать голос»), доступно через экраны панели или
  `python main.py` (консоль).
