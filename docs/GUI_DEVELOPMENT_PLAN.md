# Отчёт: план разработки GUI для JARVIS

**Дата:** 2026-09-27
**Основание:** `docs/PROJECT_ANALYSIS_REPORT.md` (анализ от 2026-09-27), `docs/WEB_PANEL_PLAN.md`, `docs/ROADMAP.md` (Приоритет 4), `docs/ARCHITECTURE.md` («GUI — WPF/MAUI оболочка вместо консоли»).
**Статус:** ВЫПОЛНЕНО — этапы 0–6 выполнены (этап 6 — оценка вариантов десктопа; вариант B внедрён: панель открывается окном WebView2 с треем — по запросу пользователя, см. §7 «Статус»)

---

## 1. Цели и задачи

**Цель:** превратить консольный цикл JARVIS в визуальный интерфейс, сохраняя все текущие возможности (диалог, память, голос, управление ПК) и не ломая архитектуру.

**Задачи:**
1. Единый экран состояния ассистента (что запущено, что сломано) — вместо чтения логов.
2. Визуальные: дашборд, чат/история, память, настройки/личности, голос, приложения/процессы, плагины, логи.
3. Безопасное управление опасными действиями (выключение, kill, удаление файлов) — GUI как место **настоящих** подтверждений.
4. Один API-контракт для обеих реализаций (C# и Python), чтобы не углублять дрейф.
5. Не превращать локальный сервер в вектор атаки (проект и так локальный, но TTS-сервер в отчёте уже отмечен как без аутентификации).

**Не-цели (первый релиз):** мульти-устройство/удалённый доступ, marketplace плагинов, мобильная версия, WPF/MAUI-нативная оболочка (см. этап 6).

## 2. Как отчёт анализа определяет дизайн и последовательность

GUI — это витрина поверх функций. Отчёт показал, что **часть витрин будет пустой или опасной, если строить её на текущем фундаменте**. Поэтому план начинается с блокеров.

| Находка отчёта | Влияние на GUI | Решение в плане |
|---|---|---|
| **P0-1** история не сохраняется, `jarvis.db` пуст | Страницы «История» и многоходовой чат будут всегда пусты | **Этап 0:** сначала `Save` в engine + реверс `BuildHistory` |
| **P0-2** path traversal в `FileManager` | «Создать файл» из GUI — та же дыра, но теперь с кнопкой | **Этап 0:** нормализация путей до появления файлового экрана |
| **P0-3** kill/удаление без подтверждения, «да» без TTL, ловит отрицания | GUI обязан дать модальное подтверждение с TTL, списком PID и путей | **Этап 0 + 4:** единый компонент ConfirmDialog (TTL 60 с, откат, «показать что именно») |
| **P1-3** плагины-обработчики мертвы, Python-загрузка сломана | Страница «Плагины» с выключателями соврёт пользователю | **Этап 4:** только после починки `PluginManager`; до тех пор — read-only список |
| **P1-4** дрейф конфига (C# не читает `voiceVolume`, Python не читает `ttsEngine`) | Настройки голоса будут «сохраняться» без эффекта | **Этап 0:** единая схема конфига + маппинг полей; API отдаёт только читаемые поля |
| **P1-1** перехваты «что такое», «найди файл» до LLM | Чат в GUI сразу проявит эти баги как «ассистент тупит» | **Этап 0:** fallthrough к LLM (иначе чат-экран невыносим) |
| **P1-2** двойной системный промпт | Ответы в чате будут хуже, чем могли бы | Включить `/api/chat` с ролями в этап 1 (API-контракт) |
| Утечка `ex.Message` пользователю | В GUI нельзя показывать сырые исключения | API отдаёт нормализованные `{code, message}`; детали — только на экране «Логи» |
| **P1-7** 0 тестов, 0 CI | REST API без контрактных тестов сломается незаметно | В этап 1 сразу: OpenAPI-спека + контрактные тесты в CI |
| TTS-сервер без аутентификации, `ProbeReady` на чужом порту | Web-панель — второй локальный HTTP-сервер; не повторять их ошибки | **Этап 1:** loopback-only, токен, проверка `Origin`, запрет `Host: не-localhost` |
| README/AGENTS дрейф (6 стилей → фактически 5) | UI не должен обещать несуществующее | Список стилей/плагинов — только из API, не хардкод |

**Вывод:** «красивый GUI на сломанном ядре» — главный риск. Этап 0 обязателен, и он почти целиком состоит из P0/P1 самих отчёта-анализа.

## 3. Выбор стека

### Варианты

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **A. Web-панель** (локальный HTTP + браузер): `HttpListener`/Kestrel + SPA | Соответствует ROADMAP 4.1 и `WEB_PANEL_PLAN.md`; один код на C# и Python; удалённый доступ потом бесплатно; быстрый итерации | Не «нативное окно»; нужна защита локального сервера | ✅ **Рекомендация** |
| B. Нативный десктоп (WPF / Avalonia) | Нативный вид, автозапуск в трее | Два GUI под две реализации (C# и Python) — дрейф удвоится; высокая цена входа; ROADMAP откладывает | ⏸ Этап 6 (после стабилизации) |
| C. TUI (цветная консоль, Textual) | Дёшево, ROADMAP 4.2 | Не закрывает задачу «внешний вид» | ❌ Как промежуточный шаг — уже в ROADMAP 4.2, вне этого плана |

### Рекомендованный стек (вариант A)

| Слой | Технология | Почему |
|---|---|---|
| Backend C# | `System.Net.HttpListener` (по `WEB_PANEL_PLAN.md`) | Без новых NuGet-зависимостей |
| Backend Python | `http.server`/`aiohttp` (или FastAPI при появлении зависимостей) | Паритет контракта, не кода |
| Контракт | **OpenAPI 3** (`docs/api/openapi.yaml`) — один на обе реализации | Защита от дрейфа; из спеки генерируются контрактные тесты |
| Frontend | Vanilla TS + lightweight-сборка (Vite), **без тяжёлого фреймворка** | Соответствует духу `WEB_PANEL_PLAN.md` (vanilla JS), минимум зависимостей |
| Real-time | **SSE** для потока ответов и статусов; WebSocket — только если SSE не хватит (ROADMAP 5.2) | SSE проще, односторонний поток ассистента — идеальный кейс |
| Стили | CSS-переменные + маленький набор компонентов (собственный, ~15 компонентов) | Полный контроль над «внешним видом» без vendor-тем |
| Тесты | Контрактные (spectral + pytest/xUnit по спеке), E2E — Playwright | Закрывает P1-7 |

## 4. Информационная архитектура

```
JARVIS GUI (SPA, раздел слева — постоянная навигация)
│
├── 🟠 Дашборд            — статусы: Ollama / Whisper / Piper / PocketTTS / память,
│                           CPU·RAM·диск, последние 5 событий, кнопка «Тест голоса»
├── 💬 Чат                — потоковый диалог (SSE), регенерация, вставка из истории,
│                           индикатор «думает/говорит», показ источника ответа (LLM/обработчик/память)
├── 🕘 История            — лента диалогов, поиск, очистка (с подтверждением), экспорт
├── 🧠 Память             — таблица воспоминаний: добавить/редактировать/удалить (с подтверждением),
│                           источник (извлечено автоматически / вручную)
├── 🎙 Голос              — выбор движка (pocket/piper), громкость, скорость, запись
│                           референса голоса, тест STT→TTS, индикация уровня микрофона
├── 🚀 Приложения         — поиск по индексу, запуск, переиндексация, просмотр алиасов
├── ⚙️ Процессы           — список PID, поиск, «завершить» → ConfirmDialog со списком PID (TTL)
├── 🎭 Личности           — карточки стилей (только фактические из API!), смена с сохранением
├── 🧩 Плагины            — read-only список до починки P1-3; затем вкл/выкл и настройки
├── 📜 Логи               — errors.log + журнал событий, фильтр по уровню
└── ⚙️ Настройки          — модель Ollama, язык, конфиг (поля-призраки скрыты),
                            бэкап/восстановление, «о программе» (версия, ветка)
```

**Сквозные компоненты (дизайн-система):**
- **ConfirmDialog** — единственный способ выполнить необратимое действие: показывает *что именно* (путь, PID, имя), TTL-таймер 60 с, кнопки «Выполнить»/«Отмена», недоступен при потере фокуса окна. Реализует требования P0-3.
- **StatusPill** — индикация сервиса (ok / degraded / down) с автопроверкой `/api/health`.
- **Toast** — уведомления, тот же канал, что и системные (ROADMAP 4.3).
- **EmptyState** — честные пустые состояния («История пуста: сохранение диалогов ещё не включено» вместо молчания).
- **ErrorBoundary** — только нормализованные ошибки API; сырые исключения не показываются (P2-1 отчёта).

## 5. Визуальная концепция (внешний вид)

### 5.1 Типографика
| Роль | Шрифт | Размер |
|---|---|---|
| Заголовки/цифры дашборда | **JetBrains Mono** (или Geist Mono) | 24–32 px, tabular-nums |
| Интерфейсный текст | **Inter** / **Manrope** | 14 px base, 1.5 line-height |
| Логи, код, команды | JetBrains Mono | 13 px |

### 5.2 Цветовая палитра (тёмная тема по умолчанию — это JARVIS)

| Токен | HEX | Назначение |
|---|---|---|
| `--bg` | `#0A0E14` | фон приложения |
| `--surface` | `#11161F` | карточки, панели |
| `--surface-2` | `#1A2130` | ховер, вложенные блоки |
| `--accent` | `#00E5FF` | акцент JARVIS (cyan), активные элементы, фокус |
| `--accent-2` | `#7C4DFF` | вторичный акцент (фиолетовый), прогресс, графики |
| `--text` | `#E6EDF3` | основной текст |
| `--text-dim` | `#8B949E` | вторичный текст |
| `--ok` / `--warn` / `--danger` | `#3FB950` / `#D29922` / `#F85149` | статусы (галка у GitHub-палитры — знакомый код) |

Светлая тема — инверсия токенов (`--bg: #F6F8FA`), акцент тот же; переключение в Настройках (ROADMAP 4.4).

### 5.3 Каркас экрана

```
┌─────────────┬──────────────────────────────────────────────┐
│  ◈ JARVIS   │  Хлебные крошки / заголовок          [⚙] [?] │
│             ├──────────────────────────────────────────────┤
│ 🟠 Дашборд  │                                              │
│ 💬 Чат      │              Основная область                │
│ 🕘 История  │         (карточки / поток чата)              │
│ 🧠 Память   │                                              │
│ 🎙 Голос    │                                              │
│ ...         │                                              │
│             ├──────────────────────────────────────────────┤
│ ● Ollama OK │  статус-строка: микрофон · индекс · версия   │
└─────────────┴──────────────────────────────────────────────┘
```

- Ширина сайдбара 220 px (свачивается в иконки ≤ 1024 px).
- Сетка дашборда: 12 колонок, карточки 4/6/12.
- **Движение:** только функциональное — пульсация индикатора «слушает/думает/говорит» (1.6 s ease-in-out), появление карточек 150 ms fade+4px, SSE-строки чата — печать. Уважать `prefers-reduced-motion`.
- **Деталь-характер:** тонкая (1 px) cyan-подсветка активного пункта навигации + мягкое свечение `box-shadow: 0 0 12px rgba(0,229,255,.25)` на акцентных элементах — фирменный «реактор», но дозированно (не более 1–2 светящихся элемента на экран).

### 5.4 Дашборд (главный экран) — приоритет композиции
1. **Ряд статусов:** Ollama · Модель · Whisper · TTS-движок · Память (N воспоминаний) — StatusPill × 5.
2. **Ряд метрик:** RAM ассистента, длина текущей сессии, команд сегодня (mono-цифры крупно).
3. **Последние события** (лента 5 строк) + кнопка быстрого действия «Тест голоса».

## 6. API-контракт (минимальный)

```
GET  /api/health              → {ollama, whisper, tts, memory:{count}, version, branch}
GET  /api/config              → читаемая конфигурация (без полей-призраков)
POST /api/config              → валидация по схеме, атомарное сохранение
GET  /api/personality          → {activeId, activeStyle, styles:[…]}   # фактический список
POST /api/personality/set      → {styleId}  (+ персист стиля — чинит P1-3)
GET  /api/chat/stream?text=…   → SSE: token* | done | error(нормализованный)
GET  /api/history?limit&offset → {items:[…]}        # работает после этапа 0
DELETE /api/history            → подтверждение в теле: {confirm:"DELETE"}
GET  /api/memory               → {items:[…]}
POST|DELETE /api/memory/{id}
GET  /api/processes?q=         → {items:[{pid,name,memoryMb,responding,protected}]}   # CPU не отдаётся — его никто не меряет
POST /api/processes/{pid}/kill → шаг 1 {} → {ttlToken}; шаг 2 {confirm:"KILL", ttlToken}   # сервер проверяет TTL
POST /api/power/{action}       → шаг 1 {} → {ttlToken}; шаг 2 {confirm:"POWER", ttlToken}  # штатный SafeActionManager
GET  /api/logs?level=&limit=&offset= → {items:[{time,level,message,source}], total}
GET  /api/apps?q=  ·  POST /api/apps/reindex → {count, durationMs}
GET  /api/plugins              → список + handlersConnected (честно: false до P1-3) + commandHandlersCount + activePersonality
GET  /api/voice                → настройки + capabilities (recordReference/pocketCloning/speechSpeedConfig/liveVolumeApply/sttTest)
POST /api/voice                → подмножество {voiceEnabled,voiceVolume,ttsEngine,voiceReferencePath} → appliedOnRestart
POST /api/voice/reference      → запись WAV-референса (C#; Python-порт отвечает 503 честно)
POST /api/voice/test           → {text ≤500} → синтез; 503, если TTS не инициализирован
POST /api/voice/listen         → распознавание фразы; 503, если STT недоступен
```

**Правила контракта:** только `127.0.0.1`; заголовок `X-JARVIS-Token` (токен генерируется при старте, кладётся в `config/panel.token`, UI читает его при загрузке); проверка `Origin/Host`; никакого исполнения строк на сервере (исходя из P1-6 отчёта — весь ввод валидируется на сервере, не доверяя UI).

## 7. Дорожная карта

| Этап | Содержание | Срок* | Зависимости | Статус |
|---|---|---|---|---|
| **0. Фундамент** | P0-1 (сохранение истории + реверс), P0-2 (пути), P0-3 (TTL/подтверждения, учёт отрицаний), P1-1 (fallthrough к LLM), P1-4 (единая схема конфига) | 1–1.5 нед | без этого GUI строить на сломанном | ✅ |
| **1. API-ядро** | OpenAPI-спека, `/api/health`, `/api/config`, SSE-чат (вместе с P1-2 `/api/chat`), токен+loopback+Origin, контрактные тесты в CI (закрывает P1-7 частично) | 1.5–2 нед | этап 0 | ✅ |
| **2. Дизайн-система + Дашборд + Настройки** | токены/темы, 15 компонентов, навигация, StatusPill, дашборд, экран Настройки + Личности (с персистом стиля) | 2 нед | этап 1 | ✅ |
| **3. Чат, История, Память** | SSE-поток, EmptyState, CRUD памяти с ConfirmDialog, история с поиском/экспортом | 1.5–2 нед | этап 2; P0-1 | ✅ |
| **4. Голос, Процессы, Приложения, Плагины, Логи** | голосовой экран (запись референса — паритет с C#), ConfirmDialog для kill/удаления/питания, read-only плагины, просмотр логов, Toast | 2 нед | этап 2; P1-5 (микрофон) | ✅ |
| **5. Полировка** | светлая тема, `prefers-reduced-motion`, клавиатурная навигация (Tab/фокус/Escape), i18n ru→en, E2E (Playwright), авто-открытие панели из консоли | 1–1.5 нед | этап 4 | ✅ |
| **6. Решение по десктопу** | Оценка WPF/Avalonia-трее поверх того же API → `docs/DESKTOP_SHELL_EVALUATION.md` (дорожка A→B; **вариант B внедрён: окно WebView2 + трей, фолбэк — браузер**) | после 5 | ARCHITECTURE.md | ✅ |

\* Оценки — календарные недели при работе по 1 этапу за раз; итого ~9–11 нед до зрелой панели, MVP (этапы 0–2) — ~5 нед.

**Гейты приёмки между этапами:**
- после этапа 0: «покажи историю» возвращает сохранённые пары; «что такое гравитация» доходит до LLM; `create_file('../x')` отклоняется; «да» через 2 минуты не выключает ПК;
- после этапа 1: контрактные тесты зелёные в CI; панель не отвечает на `Host: evil.local`;
- после этапа 2: смена стиля переживает рестарт (закрывает баг P1-3);
- после этапа 4: любое необратимое действие требует ConfirmDialog, и сервер тоже проверяет TTL (двойная защита);
- после этапа 5: E2E-смок (дашборд → чат → настройки → i18n) зелёный в CI; смена языка применяется без перезагрузки и переживает её; панель открывается в браузере из консоли;
- после этапа 6: панель открывается отдельным окном приложения (WebView2 + трей), без WebView2 Runtime — фолбэк в браузер; команда «панель» выводит окно на передний план; UI/API не изменились (83 контрактных + 5 E2E зелёные).

## 8. Риски и митигация

| Риск | Митигация |
|---|---|
| GUI построит на сломанном ядре, витрины пустые | Этап 0 как жёсткий гейт; EmptyState честно сообщает о неготовности |
| Дрейф C#/Python API | Один OpenAPI-контракт, контрактные тесты для обеих реализаций в CI |
| Локальный сервер как вектор атаки (урок TTS-сервера из отчёта) | loopback-only + токен + Origin/Host; никакого shell на сервере; аудит перед этапом 5 |
| Обещать несуществующее (стили/плагины) | Весь список возможностей — из API, не хардкод (урок «6 стилей → 5») |
| Scope creep (мультимедиа, виджеты, удалённый доступ) | Не-цели в §1; ROADMAP 5.2 — отдельно и позже |
| Сырые ошибки в UI | Нормализованные `{code,message}` на API, детали — только в «Логах» |

## 9. Критерии приёмки (финальные)

1. Все 10 экранов из §4 работают на обеих реализациях через один контракт.
2. Ни одно необратимое действие не выполняется без ConfirmDialog **и** серверной проверки TTL.
3. Нет утечки сырых исключений и внутренних путей в UI.
4. Контрактные тесты API и E2E-смок (дашборд → чат → настройки) зелёные в CI.
5. Тёмная/светлая тема, `prefers-reduced-motion`, полная клавиатурная навигация.
6. Документация `docs/WEB_PANEL_PLAN.md` обновлена до фактической реализации (закрывает README/AGENTS-дрейф).
