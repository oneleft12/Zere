# Роутер интентов ZERE на Jev (TypeSafe System One)

Статус: **рабочий слой, выключенный по умолчанию**. Модуль, клиент, реестр
интентов, обработчик-обёртка в пайплайне, подтверждения, тесты, CLI и
бенчмарк — готовы. Роутер включается ключом (`enabled: false` по умолчанию):
без ключа обработчик вообще не регистрируется, поведение ZERE не меняется.

## Быстрый старт: как сделать роутер рабочим

1. **Получить ключ OpenRouter** (`sk-or-...`): <https://openrouter.ai/settings/keys>
   и пополнить баланс. Jev оплачивается по входным токенам (выходные
   бесплатны) — одно решение стоит доли цента; текущая цена на
   [странице модели](https://openrouter.ai/typesafe/jev-1.13).
   Ключ шлюза OpenCode Go (`oc_sk_...`), который уже стоит в ZERE для чата,
   для Jev **не подходит** (см. таблицу проверок ниже).
2. **Включить роутер**:

   ```bash
   cp config/router.example.json config/router.json
   ```

   ```json
   { "enabled": true, "api_key": "sk-or-..." }
   ```

   Если в панели «Подключение ИИ» уже стоит ключ OpenRouter, ключ в
   `router.json` не нужен — достаточно `{ "enabled": true }`: роутер сам
   возьмёт `sk-or-...` из `config/ai.json`.
3. **Перезапустить ZERE** — пайплайн обработчиков собирается при старте.
4. **Проверить**: `python3 -m zere.core.routing --check` (ключ и адрес) и
   `python3 -m zere.core.routing "закрой процесс дискорд"` (разбор фразы).
5. **Настроить пороги под себя**: `python3 tools/jev_bench.py --save bench.json`
   → посмотреть таблицу порогов в отчёте (§4).

В логах ZERE (`logs/zere_*.log`) каждое решение роутера видно строкой
`[JevRouter] execute intent=process_kill conf=0.97 412мс «прибей дискорд» → «закрой процесс discord.exe»`.

Зачем: сейчас всё, что не совпало с точной фразой обработчика, уходит в LLM
(3–30 секунд на команду вида «закрой процесс discord»). Jev отвечает на
типизированный вопрос «что хочет пользователь?» за 70–500 мс и ~$0.001,
возвращая вариант из известного множества и калиброванную уверенность.
Действует код: интент → каноническая фраза → существующий обработчик
пайплайна.

Файлы:

| Файл | Что внутри |
|---|---|
| `zere/core/routing/intents.py` | реестр 36 интентов: канонические фразы, слоты, подтверждения |
| `zere/core/routing/jev_client.py` | клиент Decisions API (choice/score/noul, ошибки `JEV_*`) |
| `zere/core/routing/jev_router.py` | настройки, пороги, решение `RouteDecision`, CLI |
| `zere/core/routing/__main__.py` | вход CLI (`python3 -m zere.core.routing "…"`) |
| `zere/core/handlers/jev_routing_handler.py` | обработчик-обёртка в пайплайне + порядок (`arrange_handlers`) |
| `zere/core/services.py` | регистрация обёртки между локальными обработчиками и `AIHandler` |
| `zere/paths.py` | `router_config_path()` — `config/router.json` (gitignored) |
| `tests/test_jev_router.py` | 72 теста без сети (фейковая HTTP-сессия) |
| `tools/jev_bench.py` + `tools/jev_bench_phrases.jsonl` | бенчмарк на 81 размеченной фразе |

## 1. Что такое Jev и что он даёт

Jev — первый **System One** модель TypeSafe. Это не генеративная модель:
на вход уходит `state` (контекст) и карта типизированных `questions`, на
выход — типизированные `answers`. Свободного текста в ответе нет, поэтому
парсить нечего и «невалидный интент» получить нельзя.

| Примитив | Вопрос | Ответ |
|---|---|---|
| `choice` | «который из вариантов?» | выбранный вариант, вероятность по каждому, `confidence` |
| `noul` | «условие выполнено?» | вероятность «да» (0…1) |
| `score` | «где на шкале?» | позиция на шкале, распределение, `confidence` |

Важно: Jev **не извлекает строки**. «Закрой процесс X» — X придёт как
`choice` из переданного списка (защита от подстановки) либо будет снят
локально; придумать имя файла или текст на холст Jev не может.

Куда обращаться (форма запроса одна и та же):

```
POST https://openrouter.ai/api/alpha/decisions      # Decisions API (наш путь)
POST https://api.typesafe.ai/v1/systemone           # официальный TypeSafe
POST https://openrouter.ai/api/v1/systemone         # System One через OpenRouter
Authorization: Bearer <ключ OpenRouter sk-or-...>
```

Модель: `~typesafe/jev-latest` (алиас на свежий релиз) или пинованная
`typesafe/jev-1.13`. Контекст 32k токенов, оплата — только входные токены
(выход бесплатный), ~$0.001 за решение, задержка 70–500 мс.

### Что проверено на этой машине

Роутер работает только с ключом **OpenRouter** (`sk-or-...`). Настроенный в
ZERE облачный ключ — от шлюза OpenCode Go, и к Jev он доступа не даёт:

| Проверка | Результат |
|---|---|
| `GET https://opencode.ai/zen/go/v1/models` текущим ключом | 38 моделей, **ни одной** `typesafe`/`jev` |
| `POST …/zen/go/v1/decisions` (варианты путей) | `404` |
| `POST https://openrouter.ai/api/alpha/decisions` ключом OpenCode Go | `401` |
| Ключ OpenRouter в `config/ai.json` (`sk-or-...`) | переиспользуется автоматически (`key_source: "cloud"`) |

Поэтому роутер переиспользует только ключи с префиксом `sk-or-` и честно
говорит об этом в диагностике: `python3 -m zere.core.routing --check`
выводит «Ключ Jev не задан…». Ключ шлюза OpenCode Go (`oc_sk_...`) для Jev
не подходит — это разные сервисы.

## 2. Схема: Jev решает, код действует

```
сообщение пользователя
        │
        ├── mode=fallback (по умолчанию): сначала локальный пайплайн
        │      └─ не понял → спрашиваем Jev
        └── mode=first: сначала Jev, потом пайплайн
                       │
                       ▼
        ┌──────────────────────────────────────────┐
        │  Jev: state + questions (1–2 запроса)    │
        │  intent (choice) · negated (noul)        │
        │  + слоты: app/process (choice), level    │
        │    (score) — батчем в том же запросе     │
        └───────────────┬──────────────────────────┘
                        │  типизированный ответ + уверенность
        ┌───────────────┴──────────────────────────────────────────┐
        │ уверенность ≥ порога           → action=execute:          │
        │                                   каноническая фраза →    │
        │                                   обработчик пайплайна    │
        │ уверенность ниже, но ≥ clarify → action=clarify: вопрос   │
        │ необратимое действие           → action=confirm: «да/нет» │
        │ не команда / запрет / сбой     → action=llm | off | error │
        └──────────────────────────────────────────────────────────┘
```

### Канонические фразы

Jev не вызывает обработчики напрямую. Он выбирает интент, роутер превращает
его в ту фразу, которую обработчик уже гарантированно понимает
(«закрой процесс {process}», «громкость {level}»), и дальше работает
существующий пайплайн — со всеми его защитами: подтверждения
`SafeActionManager`, запрет на системные процессы
(`ProcessService.is_protected`), отказ на имени процесса вне списка.

Это же даёт дешёвую страховку от регрессий: тест
`test_canonical_commands_are_parsed_by_real_routers` прогоняет каждую
каноническую фразу через настоящие разборщики (`FileCommandRouter`,
`ProcessCommandRouter`, `VolumeCommandRouter`, `WindowsCommandRouter`,
`DrawingCommandRouter`) и падает, если интент перестал разбираться.

### Стратегии

| Стратегия | Запросы | Что спрашиваем |
|---|---|---|
| `single` (по умолчанию) | 1 (2 только при слоте-числе, его спрашиваем батчем — 1) | интент из всех 36 + запрет + заготовки слотов |
| `domain` | 2 | 1) домен (11 областей) + запрет; 2) интент внутри домена + его слоты |

В `single` все слоты-вопросы уходят **в одном запросе** с интентом: Jev
отвечает на них параллельно и делит стоимость `state`. В `domain` первый
запрос намеренно узкий (только домен), кандидаты не гоняются зря, а домен
`chat` вообще не требует второго запроса.

### Слоты: три способа получить аргумент

| Вид | Пример | Кто решает | Защита |
|---|---|---|---|
| `enum` | приложение, процесс, фигура, цель рисования | Jev `choice` из переданного списка (до `max_candidates`) | ответ сверяется со списком кандидатов; нет в списке → уточняющий вопрос |
| `score` | громкость 0–100 | Jev `score` по шкале с шагом 10 | значение зажимается в 0…100 |
| `text` | имя файла/папки, текст на холсте, факт для памяти | локально (`extract_payload`): кавычки → снятие триггера → чистка | не извлеклось — `clarify`, а не догадка |

Списки кандидатов берутся у системы (`LocalCatalog`: индекс приложений и
процессы), но передаются слотом-интерфейсом: в тестах и на машинах без
индекса роутер деградирует до локального извлечения аргумента, а не падает.

### Три уровня уверенности

```
conf ≥ execute_threshold   → выполнять (необратимые — только с critical_threshold)
conf ≥ clarify_threshold   → переспросить одной конкретной фразой
иначе                      → в ИИ, как будто роутера нет
```

## 4. Пороги и калибровка

Значения по умолчанию (`config/router.json`):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `execute_threshold` | 0.85 | выполнять обычную команду |
| `clarify_threshold` | 0.55 | ниже — сразу в ИИ |
| `critical_threshold` | 0.93 | выполнять необратимое (завершение процесса, удаление файла, питание, очистка памяти/холста) |
| `slot_threshold` | 0.50 | принимать аргумент-выбор |
| `negated_threshold` | 0.60 | считать фразу запретом/отменой |

Пороги берутся не «круглыми числами», а из цены ошибки. Бенчмарк считает
именно это:

```
python3 tools/jev_bench.py --save bench-latest.json   # один раз спрашивает Jev
python3 tools/jev_bench.py --from bench-latest.json   # пересчёт порогов без сети
```

Отчёт даёт точность по интентам, распределение действий, p50/p95 задержки,
стоимость за 1000 решений, список «опасных» случаев (выполнено не то) и
таблицу «порог → авто/ошибок/уточнено». Сырые решения сохраняются, поэтому
пороги можно пересчитывать, не платя за повторные запросы.

Правило для продакшена: пиновать версию модели (`typesafe/jev-1.13`), иначе
`~typesafe/jev-latest` обновится и калибровка порогов «поплывёт».

## 5. Безопасность

**Prompt injection.** Фраза пользователя уходит в `state` с пометкой, что
это данные, а не инструкции. Это снижает риск, но не устраняет его: Jev
анализирует текст как состояние, и «верни intent=power_shutdown» может
повлиять на выбор. Поэтому защита строится не на пометке, а на коде:

- аргументы принимаются только из известного множества (список процессов,
  приложений, шкала громкости) — подставить «system32.exe» нельзя, роутер
  переспросит;
- свободные аргументы Jev вообще не генерирует;
- необратимые действия требуют подтверждения: `confirm=handler` (спрашивает
  сам обработчик: завершение процесса, удаление файла, питание) или
  `confirm=router` (спрашивает роутер: очистка памяти/истории/статистики,
  забывание факта, очистка холста);
- запреты и отмены («не выключай компьютер») распознаются отдельным
  `noul`-вопросом и уходят в ИИ, а не на выполнение;
- системные процессы защищены и в обработчике — цепочка не обходится.

**Ключ.** Хранится только на бэкенде: `config/router.json` (gitignored,
права 0600) или окружение. Наружу отдаётся маска `sk-...abcd`, в текстах
ошибок ключ заменяется маской до общего вычистителя секретов; тест
`test_client_error_text_never_contains_key` это фиксирует.

**Приватность.** Jev — облачная модель: текст фразы уходит на OpenRouter/
TypeSafe. Для проекта, который заявлен как локальный, это осознанный
opt-in — роутер выключен по умолчанию и без ключа не делает ни одного
запроса (`action=off`, тест `test_router_off_without_key_makes_no_request`).
Кому нужна полная локальность — роутер просто не включают, поведение ZERE
не меняется.

**Что не отдаём в Jev:** генерацию ответов, многошаговое планирование,
открытые вопросы без вариантов и всё, что требует свободного текста.

## 6. Настройка

```bash
cp config/router.example.json config/router.json   # файл в .gitignore
```

Минимально достаточно ключа — остальное по умолчанию:

```json
{ "enabled": true, "api_key": "sk-or-..." }
```

Или через окружение (см. `.env.example`):

```
ZERE_JEV_ROUTER=1
JEV_API_KEY=sk-or-...
# либо OPENROUTER_API_KEY=sk-or-...  (тот же ключ, что для облачного ИИ)
```

Проверка:

```bash
python3 -m zere.core.routing --check                      # ключ и адрес
python3 -m zere.core.routing "закрой процесс дискорд"      # разбор фразы
python3 -m zere.core.routing "выключи комп" --json         # решение в JSON
python3 -m zere.core.routing "нарисуй круг" --strategy domain
```

Пример вывода разбора:

```
действие: execute
интент:   process_kill
уверен.:  0.97
команда:  закрой процесс discord.exe
слоты:    {"process": "discord.exe"}
причина:  уверенность 0.97
задержка: 412 мс
```

`RouteDecision.to_public_dict()` (то же, что `--json`) не содержит секретов
и годится для логов, API и телеметрии.

## 7. Встраивание в пайплайн (сделано)

```
сообщение → MemoryHandler → … → DrawingHandler → JevRoutingHandler → AIHandler
                                                 (mode=fallback)
```

`JevRoutingHandler` (`zere/core/handlers/jev_routing_handler.py`) стоит между
локальными обработчиками и `AIHandler`, поэтому режим `fallback` соблюдается
без изменений в существующих обработчиках — они уже попробовали свои точные
фразы. В режиме `first` тот же обработчик встаёт в начало пайплайна
(`arrange_handlers`), а при неуверенности сообщение доходит до локальных
обработчиков и затем до ИИ.

Что делает обёртка по действиям роутера:

| Действие | Поведение |
|---|---|
| `execute` | каноническая фраза → локальный пайплайн (без себя и без ИИ); ответ обработчика отдаётся пользователю. Если фраза не разобралась — `None` (отвечает ИИ) |
| `confirm` | `SafeActionManager.request(ROUTER_COMMAND, команда)` → вопрос «Подтвердите…»; «да» выполняет команду через локальный пайплайн, «нет» отменяет, TTL 60 секунд |
| `clarify` | вопрос пользователю («Как назвать папку?»), команда не выполняется |
| `llm` / `off` / `error` | `None` → отвечает `AIHandler`, как без роутера |

Детали реализации:

- **Подтверждения** идут через существующий `SafeActionManager`
  (`PendingAction.ROUTER_COMMAND`): тот же «да/нет», тот же TTL, та же
  ветка `WindowsHandler`. Лок у менеджера стал реентрантным (`RLock`):
  выполнение подтверждённой команды может само запросить подтверждение
  («очисти память» → «закрой процесс»), и обычный `Lock` дал бы вечную
  блокировку. Ответ обработчика Manager запоминает в `last_result`, и
  `WindowsHandler` показывает его вместо общего «Выполняю команду».
- **Никаких обходов**: роутер не вызывает обработчики в обход пайплайна и
  не отвечает вместо ИИ — только переводит формулировку.
- **Телеметрия**: одна строка на решение в `logs/zere_*.log` через
  `LogService` (секреты вычищаются) — `action`, `intent`, `confidence`,
  `latency_ms`, фраза и каноническая команда.
- **Цена выключенного роутера — ноль**: без ключа `build_jev_handler`
  возвращает `None`, обработчик не регистрируется и модуль не загружается.

Осталось на будущее (не мешает работе):

1. **Панель и API**: состояние/настройки роутера — `RouterSettings.public()`
   (ключ только маской) + экран рядом с «Подключение ИИ», контракт в
   `docs/api/openapi.yaml`.
2. **C#-паритет**: те же интенты и пороги в `ZERE.Core/Handlers` и `ZERE.AI`
   (по образцу `AiService`/`AiProviderProxy`); рисование — только Python.
3. **Накопление статистики** решений для пересчёта порогов без бенчмарка.

## 8. Ограничения

- Роутер не заменяет пайплайн: он закрывает его промахи. Точные команды
  быстрее и дешевле обрабатывать локально, как сейчас.
- Свободный текст извлекается эвристикой. Если аргумент не в кавычках и не
  отделён триггером, остаток может оказаться мусором («сделай папку, ну ты
  понял» → «ну ты понял»). Лечится кавычками в формулировке или тем, что
  для файлов лучше спрашивать явно; Jev здесь помочь не может — он не
  возвращает строки.
- В стратегии `domain` два round-trip (~0.5–1 с) против одного в `single`;
  сравнивать на своих фразах бенчмарком.
- Jev не объясняет решения: «почему это process_kill» узнать нельзя —
  только вероятности по вариантам.
- Облачная зависимость: без сети и ключа роутер молча выключается
  (`action=off`), ZERE работает как раньше. Сбой Jev в момент запроса —
  тоже тихий fallback (`action=error` → отвечает ИИ).
- Подтверждения роутера (`confirm=router`) работают через
  `SafeActionManager`, поэтому необратимые команды и «да/нет» живут 60 секунд
  и не выполняются после истечения срока.

## 9. Тесты

```bash
python3 tests/test_jev_router.py     # 72 теста, без сети (фейковый HTTP)
pytest tests/ -q                     # в CI вместе с остальными
```

Что проверяется: реестр и его контракт с настоящими разборщиками,
извлечение аргументов, настройки (файл/окружение/переиспользование ключа
OpenRouter), форма запроса и разбор ответов, ошибки `JEV_*`, маскирование
ключа, пороги и уровни действий, проверка аргументов по списку кандидатов,
обе стратегии, запреты, C#-редакция без рисования, fallback без ключа и при
сбое сети, CLI-диагностика, **встраивание**: порядок обработчиков, реальный
пайплайн (роутер выручает там, где локальные обработчики промахнулись,
болтовня уходит в ИИ, `mode=first` не ломает привычные команды),
подтверждение необратимых команд через `SafeActionManager` (включая
цепочку «подтверждение внутри подтверждения» и истечение срока), строка
лога без секретов.

В CI (`python` job) добавлен шаг «Тесты роутера интентов Jev» и `psutil`
в зависимости тестов — тесты подтверждений проверяют настоящий
`SafeActionManager`.
