# Отчёт о проверке: агент ZERE и локальная веб-панель

- **Дата:** 2026-10-06
- **Проверяющий:** агент DSH (по плану «План проверки агента JARVIS с веб-панелью»)
- **Версия:** `1.8.0`, ветка `python-port`, коммит `35397d7`
- **Объект проверки:** реальный HTTP-сервер панели `zere/api/server.py` (`PanelServer`),
  собранный SPA `panel/dist/`, контракт `docs/api/openapi.yaml`, автотесты `tests/` и `panel/e2e/`

## 0. Окружение и ограничения

| Параметр | Значение |

| Python | 3.14.4 (системный), 3.14.7 (Windows `.venv`, в WSL не запускается) |

Дополнительно устанавливалось **только во временные каталоги** (система не менялась):
`pip install --target /tmp/zerepy psutil mss pytest`, распаковка `libnspr4/libnss3/libasound2t64`
из `.deb` в `/tmp/pwlibs` (для запуска Chromium без root).

**Ключевое ограничение:** реальный агент в WSL не импортируется — `zere/tools/windows/volume/volume_service.py`
на уровне модуля требует `pycaw` (Windows-only). Поэтому API-проверки велись против **настоящего**
`PanelServer` (тот же код, что в проде: токен, Host/Origin, статика, SSE, TTL-подтверждения),
но с фейковыми доменными сервисами (`tests/e2e_server.py`) и без LLM.
Это ограничение среды: продукт заявлен как Windows-only.

## 4. Связь панели и агента

- **Канал:** HTTP/1.0 + SSE (`GET /api/chat/stream`) — контракт совпадает с `docs/api/openapi.yaml` (20 путей).
- **Клиент:** `panel/src/api.ts` — `fetch` + `ReadableStream` (не `EventSource`, потому что нужен заголовок токена).
- При недоступности бэкенда клиент отдаёт нормализованную ошибку
  `{code:"NETWORK", message:"Панель недоступна — бэкенд не отвечает."}` — без стеков и внутренних путей.
- Проверенные ответы: `401 UNAUTHORIZED` (нет/неверный токен), `403 FORBIDDEN_HOST`,
  `403 FORBIDDEN_ORIGIN`, `404 NOT_FOUND`, `405` на неверный метод, `400 VALIDATION_ERROR`
  (пустой текст, >4000 символов, битый JSON, лишние ключи), `200` на корректные.
- Граница длины: 3999 → 200, 4000 → 200, 4001 → 400 «Текст слишком длинный (максимум 4000 символов)».
- Одно соединение = один запрос (HTTP/1.0, без keep-alive) — замечание В7.

Политика опасных действий (чёрный ящик, `POST /api/power/{action}`):

1. тело `{}` → `{"status":"pending","ttlToken":"…","expiresInSeconds":60}`;
2. `{confirm:"POWER"}` без токена → 400 `Отсутствует обязательный ключ: «ttlToken»`;
3. `{confirm:"POWER", ttlToken:"00…00"}` → 400 `TTL_EXPIRED` — **и гасит ожидающее действие**
   (токен одноразовый, неверная попытка аннулирует подтверждение);
4. свежий шаг 1 + верный токен → `{"status":"executed"}`;
5. неизвестное действие → 404 `Неизвестное действие питания`;
6. `confirm` не равен `"POWER"` → 400 `Ожидалось подтверждение confirm = "POWER"`.

## 15. Что не проверено в этом прогоне

1. Реальные ответы LLM (нет Ollama) — проверялся транспорт и обработка недоступности внешнего API.
2. Реальные команды устройства (свет/музыка/напоминания) — в проекте ZERE их нет как класса;
   опасные действия (питание, kill процесса) проверены на уровне политики подтверждения.
3. Windows-специфичные инструменты (громкость `pycaw`, скриншоты `mss`, голос `sounddevice`) — вне Linux.
4. C#-реализация панели (`ZERE.App/Api/PanelServer.cs`) — нет .NET SDK; в CI она гоняется теми же 91 тестом.
5. Длительная стабильность 1/8/24 ч — выполнен 5-минутный soak (см. §7); долгий прогон не заказывался.
6. WebKit/Safari, Edge, инкогнито-режим как отдельные конфигурации.

## 17. Как воспроизвести

```bash
# контракт API (91 тест, нужен pyyaml)
python3 tests/test_panel_api.py

# полный набор (нужен pytest)
python3 -m pytest tests/ -q

# сборка фронтенда
cd panel && npm ci && npm run build

# E2E-смоук (сервер поднимает сам, порт 8099)
cd panel && npm run test:e2e

# расширенный браузерный аудит (порт 8101; убивает и перезапускает сервер)
cd panel && NODE_PATH=$PWD/node_modules node e2e/audit.cjs
```

На Linux без root браузеру нужны `libnspr4`, `libnss3`, `libasound2`; их можно распаковать
локально и передать каталог в `LD_LIBRARY_PATH` (см. комментарий в `panel/playwright.config.ts`).
