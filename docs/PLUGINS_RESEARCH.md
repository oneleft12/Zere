# Плагины для ZERE — ресерч (октябрь 2026)

**Вопрос:** какие плагины реально подходят ZERE и что нужно сделать, чтобы они
заработали.

**Дата:** 14 октября 2026. **Контекст:** ZERE 1.8.0, две редакции (C# .NET 10 и
Python), офлайн-первый принцип, Windows, целевое железо — слабый ПК (4–16 ГБ RAM,
CPU-only), интерфейс — консоль + веб-панель. Плагинная система объявлена в коде,
но обработчики не подключены к конвейеру (известный пункт P1-3 аудита).

---

## 1. Краткое резюме

1. **Плагинная система сегодня не работает для обработчиков.** `ICommandHandlerPlugin`
   загружается и попадает в счётчик, но в пайплайн не встраивается: обе редакции
   честно отдают `handlersConnected=false`. Внешние Python-плагины не грузятся
   вообще — в загрузчике сравнение строки с объектом модуля.
2. **Поэтому вопрос не «какой плагин поставить», а «какой транспорт расширений
   выбрать».** Их ровно два: свой контракт в процессе и MCP (Model Context Protocol).
3. **MCP — фактический стандарт 2026 года** для инструментов ИИ-ассистентов: есть
   официальный реестр, официальные SDK для C# и Python и сотни готовых серверов.
   Взять его — значит не писать свой реестр плагинов.
4. **У MCP есть жёсткое требование — tool calling, которого в ZERE нет вовсе**
   (проверено: ни в Python, ни в C# нет ни `tools`, ни `tool_calls`). При этом
   семейство `qwen3.5`, которое ZERE предлагает по умолчанию, помечено в Ollama
   как `tools` (размеры 0.8b, 2b, 4b, 9b, 27b, 35b, 122b), а Ollama умеет tool
   calling и в родном `/api/chat`, и в OpenAI-совместимом `/v1`, который ZERE уже
   использует.
5. **Главный вывод: MCP можно подключить без tool calling.** В ZERE уже есть
   рабочий паттерн «роутер интентов → каноническая команда» (Jev). Тот же приём
   даёт «фраза → MCP-инструмент» и работает офлайн и на слабом CPU, где малая
   модель инструменты вызывает ненадёжно.
6. **Топ-3 плагина по соотношению «польза / работа»:** браузер (Playwright MCP),
   умный дом (Home Assistant MCP), заметки (Obsidian). Погоду, калькулятор и
   переводчик плагинами делать не надо — это дешевле встроенными обработчиками
   или локальной моделью.
7. **Безопасность — главный тормоз, а не техника.** Локальный MCP-сервер по
   спецификации — это обычный процесс с правами пользователя, а не песочница;
   все серверы делят один контекст модели, поэтому один зловредный влияет на
   использование инструментов всех остальных.

## 3. Развилка: свой контракт или MCP

### 3.1 Вариант A — достроить свой контракт

Дописать `MemoryProvider`/`VoiceEngine`, починить загрузчик Python, встроить
`command_handlers` в пайплайн перед `AIHandler`, добавить вкл/выкл и настройки.

**Плюсы:** нет накладных расходов и подпроцессов; работает офлайн by design; полный
контроль над правами; ровно ложится на текущую архитектуру.
**Минусы:** экосистемы нет — каждый плагин пишет пользователь под конкретный ZERE;
`.dll`/`.py` исполняются в процессе ZERE без песочницы (аудит уже отметил это как
риск: `Assembly.LoadFrom` без allowlist и подписи); свой формат манифеста,
версионирование, документация, тест-фреймворк и маркетплейс — всё своё
(это пункты 5.1 ROADMAP).

### 3.2 Вариант B — MCP-клиент в ядре

Добавить в ядро один **встроенный** обработчик, который ходит к MCP-серверам.

**Плюсы:** готовая экосистема и реестр; SDK для обеих редакций; плагин пишется
один раз и работает ещё в десятке хостов; расширять ZERE смогут те, кто не знает
ни C#, ни Python-API ZERE.
**Минусы:** нужен tool calling (или свой роутинг); каждый сервер — подпроцесс
(запуск, память, время старта — критично на слабом ПК); безопасность не решается
протоколом; Node.js для части серверов.

### 3.3 Вариант C — гибрид (рекомендация)

- **Свой контракт** — для «горячего» локального пути: команды, которые должны
  отвечать за миллисекунды без запуска подпроцессов (громкость, процессы, файлы,
  рисование, память).
- **MCP** — для «холодного» внешнего пути: браузер, умный дом, заметки, календарь,
  почта. Это то, что ZERE сам никогда не напишет, и то, что живёт вне его процесса.

Практически: MCP-клиент — это **один встроенный обработчик** рядом с `AIHandler`,
а не плагин. Тогда мёртвый `ICommandHandlerPlugin` не блокирует экосистему, и
порядок работ меняется: MCP-путь можно включить раньше, чем починен P1-3.

| Python SDK | `mcp` (PyPI, 2.0.1) — официальный, и серверы, и клиенты |

| Реестр | `registry.modelcontextprotocol.io` — официальный, с API |
| Локальные модели | Ollama: `tools` в `/api/chat` и в OpenAI-совместимом `/v1` (ZERE уже использует `/v1`); семейство `qwen3.5` помечено `tools` |

поэтому детерминированный роутинг остаётся основным путём.

## 5. Какие плагины подходят ZERE

Оценка по четырём фильтрам проекта: **офлайн**, **слабый ПК**, **Windows**,
**русский язык пользователя**.

### Уровень 1 — ставить первыми

| Плагин | Что даёт ZERE | Требует | Офлайн |
|---|---|---|---|
| **Playwright MCP** | Управление браузером по accessibility-снимкам, без vision-модели: «открой сайт», «найди на странице», «заполни форму». У ZERE контроля браузера нет вообще | Node.js + браузер | да |
| **Home Assistant MCP** (`homeassistant-ai/ha-mcp`, 5k★; `driin0/ha-mcp-server` — 182 инструмента) | Голосовое управление умным домом по локальной сети: свет, климат, сцены. Ровно то, что ассистент должен уметь | инстанс Home Assistant в LAN | да (LAN) |
| **Obsidian MCP** | Поиск и правка заметок в локальном markdown-хранилище. Дополняет SQLite-память ZERE: память — факты о пользователе, заметки — его база знаний | локальное хранилище | да |
| **Filesystem MCP** (эталонный, `@modelcontextprotocol/server-filesystem`) | Многошаговые файловые операции для LLM | — | да |
| **Windows-автоматизация MCP** (`RandyNorthrup/win32-mcp-server` — 53 инструмента; `Harusame64/desktop-touch-mcp`) | Управление произвольными приложениями, UI Automation | — | да |

**Оговорка по двум последним:** у ZERE **уже есть** `FileManager`/`FileHandler`,
`ProcessService`, `VolumeService`, `ScreenCaptureService` и рисование через
Win32/UIA. Filesystem MCP и Windows-MCP дублируют существующее, но дают то, чего
нет: **многошаговые сценарии**, где решение принимает модель («найди в папке
счета за квартал, сложи суммы, положи результат в файл»). Брать их стоит ради
этого, а не ради одиночных команд — одиночные быстрее и надёжнее родными
обработчиками.

### Уровень 2 — только при подключённом облаке или сети

| Плагин | Комментарий |
|---|---|
| **Google Calendar / Gmail MCP** | У Google есть **официальные** удалённые MCP-серверы Workspace. Закрывает пункты 3.4 ROADMAP (календарь, почта), но требует OAuth и сети — противоречит офлайн-принципу, поэтому только как опция |
| **Погода** | Есть MCP-серверы, но честнее встроенный обработчик: один HTTP-запрос, никаких подпроцессов, кэш на 10 минут. Плагин здесь — лишний слой |
| **Telegram-уведомления** (ROADMAP 3.4) | Не MCP, а исходящий вызов API: дешевле встроенным сервисом уведомлений |

### Уровень 3 — не делать плагинами

| Кандидат | Почему нет |
|---|---|
| **Переводчик** (ROADMAP 3.4, DeepL) | Локальная модель проекта переводит сама; внешний API добавляет ключ, сеть и задержку без выигрыша |
| **Калькулятор, конвертер валют** (ROADMAP 3.4) | Детерминированный код. Калькулятор — 30 строк обработчика; курсы — один запрос с кэшем. Плагинная инфраструктура дороже самой задачи |
| **Облачные SaaS-серверы из реестра MCP** | Реестр на октябрь 2026 в значительной части состоит из удалённых коммерческих серверов (реклама, лиды, недвижимость, магазины) — это и противоречит офлайн-принципу ZERE, и добавляет канал утечки в промпт |
| **Всё, что требует модели 12B+** | Противоречит целевому железу проекта |

## 6. Безопасность (без этого раздел 5 опасен)

Официальная документация MCP прямо говорит, что локальный сервер — не плагин в
песочнице:

- **stdio — общая зона доверия.** «Клиент и stdio-сервер делят один домен доверия…
  сервер уже имеет исполнение кода на вашей машине по факту запуска, поэтому
  границы между процессами, которую мог бы обеспечить транспорт, не существует».
- **Что сервер может трогать:** переменные окружения, SSH-ключи, облачные
  учётки, профили браузера, домашний каталог, исходящую сеть — «ничто из этого не
  регулируется протоколом, это регулируется тем, как вы запускаете процесс».
- **Доверие накапливается.** «Каждый сервер, который вы настраиваете, делит один
  контекст модели, поэтому зловредный сервер может влиять на то, как агент
  использует инструменты всех остальных».
- **Угрозы:** зловредный сервер (тайпсквоттинг, захваченный проект), чрезмерно
  собирающий сервер, скомпрометированная зависимость, отравленный каталог
  инструментов.
- **SEP-1024:** клиент, предлагающий установку в один клик, обязан показать
  точную команду запуска **до** запуска.

Что из этого следует для ZERE:

1. **`config/mcp.json` с явным allowlist** — сервер не запускается, пока
   пользователь не подтвердил команду. Панель показывает команду целиком
   (требование SEP-1024), а не «включить плагин».
2. **Пиннинг версий** серверов (`@modelcontextprotocol/server-filesystem@X.Y.Z`),
   а не `@latest` — иначе обновление приносит чужой код в ваш контекст.
3. **Необратимые инструменты — через существующий `SafeActionManager`**
   (`PendingAction`, TTL 60 с): подтверждение уже реализовано для роутера Jev,
   тот же механизм нужен для MCP.
4. **Отдельные права и изоляция** для серверов, которым не нужен полный доступ:
   ограничение рабочего каталога, отдельный профиль, отключение сети там, где она
   не нужна.
5. **Тот же урок для своего контракта:** загрузка `./plugins/*.dll` и `*.py` без
   allowlist и подписи — это ровно та же дыра (отмечена в `PROJECT_AUDIT_REPORT.md`,
   пункт 7). Маркетплейс плагинов из ROADMAP 5.1 без этих мер выпускать нельзя.

## 7. План внедрения

### Фаза 1 — вернуть к жизни свой контракт (малый объём, высокая ценность)

1. Починить загрузчик внешних Python-плагинов: `obj.__module__ == module` →
   `== module.__name__` (`zere/core/plugins/plugin_manager.py:134`). Плюс тест.
2. Встроить `command_handlers` в пайплайн **перед** `AIHandler` (и после локальных
   обработчиков) — в обеих редакциях, с тестом «плагин получил сообщение».
3. Перевести `handlersConnected` в `true` только когда это правда (флаг уже есть —
   он и станет индикатором готовности).
4. Добавить в `config/plugins.json` вкл/выкл и настройки плагина, включить
   переключатели на экране «Плагины» (сейчас read-only).
5. Allowlist: плагин загружается только если он в конфиге.

### Фаза 2 — MCP-клиент как встроенный обработчик (основная работа)

1. `McpClientHandler` перед `AIHandler`: держит пул подключений к серверам из
   `config/mcp.json`, отдаёт список инструментов.
2. **Два режима маршрутизации:**
   - *детерминированный* (по умолчанию) — фраза → инструмент, тем же приёмом, что
     Jev-роутер; работает офлайн и на слабом CPU;
   - *tool calling* (опция) — когда выбран облачный ключ или модель 4B+, у которой
     инструменты вызываются стабильно.
3. `SafeActionManager` для инструментов, помеченных необратимыми.
4. Панель: список серверов, их инструменты, команда запуска, вкл/выкл, статус
   процесса. Это закрывает пункт 4.1 ROADMAP «управление плагинами».
5. Тесты без сети: фейковый MCP-сервер (по образцу `tests/fake_http.py`).

### Фаза 3 — первые плагины

1. Playwright MCP — самый большой прирост возможностей при нулевой цене по ключам.
2. Home Assistant MCP — если есть умный дом; локально, по LAN.
3. Obsidian MCP — если есть хранилище заметок.
4. Google Calendar/Gmail — опционально, только для облачного режима.
5. Шаблон плагина и документация API (ROADMAP 5.1) — уже после того, как контракт
   реально работает.

## 8. Что не делать

- **Не писать маркетплейс** до allowlist, подписи и подтверждения команды.
- **Не тащить tool calling как обязательное условие.** Он превратит офлайн-режим
  на слабом ПК в лотерею; детерминированный роутинг даёт 90 % пользы.
- **Не дублировать родные возможности плагинами.** Громкость, процессы, файлы,
  рисование, память у ZERE уже есть и работают быстрее любого подпроцесса.
- **Не добавлять облачные MCP-серверы в офлайн-сборку** — это ломает главное
  обещание проекта.
- **Не удалять `ICommandHandlerPlugin`.** Аудит предлагал «подключить или удалить»;
  после фазы 1 он становится рабочим и нужен для локальных плагинов, где MCP
  избыточен.
