# Отчёт: анализ проекта JARVIS

**Дата:** 2026-10-05
**Ветка:** `python-port` (HEAD `c2259f1`), рабочая копия содержит некоммитный WIP (см. §12)
**Метод:** разведка репозитория + три параллельных аудита (документы, Python-часть, C#-часть и паритет) с **личной проверкой каждого утверждения**, выносимого в отчёт. Дополнительно фактически запускались: `scripts/check_port.py`, все Python-тесты, сборка панели, Playwright E2E.
**Окружение:** WSL/Linux, `dotnet` отсутствует → C# **не собирался**. Часть выводов по C# — статический анализ кода.

## 1. Резюме

**JARVIS** — локальный (offline-first) AI-ассистент для Windows: консоль + голос + локальная LLM (Ollama) + локальная веб-панель, управляет приложениями, файлами, процессами, громкостью и питанием. Реализован **дважды**: исходное C#-решение (.NET 10, 6 проектов, 13 991 строка) и Python-порт (пакет `jarvis/`, 12 282 строки), зеркальный по структуре почти 1:1.

**Главный вывод.** Проект технически зрелый: слойность, DI, единый конвейер обработчиков, продуманная безопасность панели, богатая документация (15 документов, ~4 600 строк), работающий CI и 110 проходящих тестов. За время с прошлого анализа (2026-09-27) **закрыты все три P0** — история диалогов, path traversal, срок жизни подтверждения. Но появился и усилился **стратегический риск: две живые реализации одной функциональности**. Установщик по умолчанию ставит Python-редакцию (`install.ps1:55`), при этом дефолтная ветка GitHub `main` отстаёт на 69 коммитов и **вообще не содержит Python-порта**, а редакции **используют разные файлы БД** и разные корни ресурсов — данные между ними не разделяются.

**Оценки (мои, с учётом динамики):**

## 4. Архитектура: что устроено хорошо

- **Единый конвейер** из 9 обработчиков (`HandlerPipeline`) с корректной изоляцией ошибок: исключение в одном обработчике логируется и **не роняет** конвейер (`handler_pipeline.py:17-32`, `HandlerPipeline.cs:20-35`), сверху страхует `JarvisEngine`.
- **DI в ядре**: `ServiceRegistration.Create` / `ServiceContainer` — зависимости приходят в конструктор, а не создаются внутри.
- **Безопасность панели (обе редакции)** — самая сильная часть: привязка строго к loopback, allow-list `Host` (защита от DNS-rebinding) и `Origin`, токен через сравнение в постоянном времени (`hmac.compare_digest` / `FixedTimeEquals`), лимит тела 64 КБ, нормализованные ошибки без сырых исключений, защита статики от path traversal, двухшаговое подтверждение kill/power с одноразовым токеном и TTL 60 с.
- **Фолбэки голосового стека**: GigaAM → Whisper (STT), PocketTTS → Piper (TTS), wake word намеренно на Whisper; микрофонные фолбэки; общий инстанс Whisper корректно инжектится в детектор (двойная загрузка модели исправлена).
- **Аннотации типов** в Python практически полные (427/428 параметров), 101 из 135 модулей с docstring, каждый модуль помечен «порт X.cs» — трассируемость к исходнику.
- **Разумные пути и безопасность процессов**: текст в Piper идёт через `stdin`, в голосовом слое `shell=True` нет; provider-независимые таймауты у Ollama и STT.
- **Установщик**: `install.ps1 -CheckOnly` (dry-run), проверка всех скачиваний по SHA-256, `uninstall.ps1` не трогает исходники, Inno Setup-сборка из `git archive HEAD`.

## 7. Главный стратегический риск: две реализации (≈93 % дублирования)

Обоснование оценки: C#-специфичны ≈818 строк (5,8 % — `PocketTtsService.cs` 453, `PanelWindow.cs` 165, `StreamPlayer.cs` 78, `SpeechText.cs` 66, `AudioOutputFactory.cs` 56); Python-специфичны ≈5 % (`paths.py`, `voice_mode.py`). Остальное — построчные пары с комментарием «Порт X.cs».

**Последствия, подтверждённые фактами:**

1. **CI не ловит рассинхронизацию.** 91 контрактный тест проверяет HTTP-форму и проходит на обеих реализациях, но не видит расхождений по существу (§8).
2. **Данные несовместимы** (§6.1 #6) — переключение редакций теряет память.
3. **Каждая фича правится дважды.** Свежий пример прямо в рабочей копии: WIP «выбор устройства вывода» сделан **зеркально** — `jarvis/voice/audio/audio_device.py` (112 строк) + `JARVIS.Voice/Audio/AudioOutputFactory.cs` (56 строк) + правки в 5 файлах с обеих сторон.
4. **Установщик разошёлся с кодом**: по умолчанию ставится Python-редакция, а `main` (дефолтная ветка) содержит только C#.

**Рекомендация.** Зафиксировать одну редакцию как **продуктовую** (кандидат — Python: она у 설치щика по умолчанию и не требует .NET SDK), а вторую перевести в режим «референс, обновляется только по необходимости». Критично, чтобы у них был **общий** каталог данных (`%LOCALAPPDATA%\JARVIS`), иначе двойной запуск будет тихо расходиться.
