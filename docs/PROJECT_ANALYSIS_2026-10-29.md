# Отчёт: анализ проекта ZERE — чего не хватает

**Дата:** 2026-10-29
**Ветка:** `python-port`, HEAD `dc5087c` («Подпись: sign.ps1…»)
**Область:** Python-пакет `zere/` + `main.py`, C#-решение (7 проектов, .NET 10), панель `panel/`, тесты, установщик, CI, документация, git-история.
**Метод:** прогон всех тестов, измерение покрытия, статический анализ (ruff), сборка панели, попытка E2E, сверка маршрутов с OpenAPI, сверка заявлений документации с кодом, анализ git-истории и ветвей.

## 1. Резюме

Проект в рабочем состоянии: **753 теста проходят**, панель собирается, `check_port.py` чист, контракт OpenAPI совпадает с сервером, секретов в трек-коде нет. С прошлого отчёта (2026-10-21) добавлены приложение-окно, установщик на `csc.exe` и подпись.

Чего не хватает — по убыванию важности:

1. **CI прогоняет 61 % тестов** (459 из 753). 13 файлов не подключены, включая конспектор, MCP, ChatTTS и KWS.
2. **Ядро не покрыто тестами вообще**: все обработчики команд, `ZereEngine`, `services.py` — 0 %; `SafeActionManager` — 11 %, `ProcessService` — 3 %.
3. **Юридический блок пуст**: нет `LICENSE` (при заявленном MIT), нет THIRD-PARTY-NOTICES/EULA/Privacy.
4. **Релизного процесса нет**: нет тегов и CHANGELOG (файл `CHAGELOG.md` — с опечаткой, заканчивается на v1.1 при версии 1.8.0); `origin/main` отстаёт на 147 коммитов, то есть на GitHub по умолчанию лежит версия от 22 сентября.
5. **Обновление не работает у установленных сборок**: `UpdateService` требует `.git`, а Setup.exe ставит `git archive` без него.
6. **Настройка `language` ни на что не влияет**: интерфейс переводится, ассистент всегда отвечает по-русски.
7. **Техдолг**: 694 строки недостижимого кода, один реальный дефект в аварийном пути (`NameError`), конвейер не сериализован, лог без ротации.

## 5. Найденные дефекты

### 5.1 `NameError` в аварийном пути сборки сервисов

`zere/core/services.py:382` вызывает `log_error(...)`, но **`log_error` в модуль не импортирован** (импортирован только `LogService`, строка 35). Это обработчик исключения в `_create_jev_handler`: если роутер Jev включён и его сборка падает (`RouterSettings.load`, конструктор `JevIntentRouter`), вместо честного отката на обычный конвейер приложение получит `NameError` при старте. Ошибка видна ruff как `F821`.

### 5.2 `language` в конфиге — мёртвая настройка

`ZereConfig.language` (`zere/core/configuration/zere_config.py:37`) читается, показывается при старте (`main.py:96`) и **больше нигде не используется**. `AIHandler._LANGUAGE_RULE` жёстко требует русский. В панели на экране «Настройки» поле «Язык» с подсказкой «Двухбуквенный код: ru, en» — пользователь ждёт переключения, но ответы останутся русскими (язык интерфейса задаётся отдельно, в localStorage).

### 5.3 Прочие замечания линтера (уровень F)

| Место | Замечание |
|---|---|
| `zere/tools/drawing/drawing_geometry.py:265–295` | `Optional` не импортирован (спасает `from __future__ import annotations`, но это ловушка) |
| `zere/voice/silero/silero_text.py:202` | ключ словаря `"км/ч"` повторяется (значение то же — безвредно, но признак копипасты) |

| `main.py:465` | замыкание над переменными цикла (`B023`) — сейчас безопасно, но хрупко |
| `zere/core/dependencies/dependency_checker.py:8` | неиспользуемый `shutil` |

### 5.4 Системные слабости

- **Конвейер не сериализован.** `ZereEngine.process()` вызывается из трёх потоков: консоль (`main.py:343,554`), панель (`zere/api/server.py:1556`), голосовой цикл (`zere/api/server.py:167`). `SafeActionManager` и `AiService` защищены своими блокировками, остальное состояние обработчиков — нет. Отчёт 2026-10-21 это фиксировал; изменений нет.
- **158 обработчиков `except Exception`** в Python-коде — ошибки глотаются, диагностика держится на логах.
- **Логи без ротации**: `LogService` создаёт новый `zere_<дата>.log` на каждый старт, `logs/errors.log` растёт без ограничения (сейчас 75 КБ).
- **Нет лимита на размер `logs/`** и очистки старых файлов.

## 6. Чего не хватает в продукте

### 6.1 Обновление недоступно установленным пользователям

`UpdateService` отказывает без `.git` (`zere/core/update/updater.py:374`). Установщик `ZereSetup.exe` наполняется через `git archive HEAD` (`installer/build-installer.ps1:140`) — `.git` в дистрибутив не попадает. Итог: экран «Обновления» и автопроверка работают только в клоне репозитория; для основного канала доставки нужен манифест версий (JSON на GitHub Releases) и обновление архивом, а не `git pull`.

### 6.2 Автозапуск, трей, горячая клавиша

- В Python-редакции нет ни иконки в трее, ни сворачивания в трей: закрытие окна завершает приложение. Трей есть только в C# (`ZERE.App/Api/PanelWindow.cs:20`).
- Нет автозапуска при входе в систему: установщик создаёт ярлыки на рабочем столе и в меню «Пуск» (`installer/install.ps1:943–983`), но ничего не кладёт в `Startup`.
- Нет глобальной горячей клавиши для вызова окна.

### 6.3 Проактивность и уведомления

Напоминаний/таймеров нет вовсе (`grep "напомн"` по коду пуст), системных toast-уведомлений тоже. Это пункт 2.2 ROADMAP и «Ставка 2» из `docs/FEATURE_IDEAS_2026-10-22.md`.

### 6.4 «Что на экране» / OCR

`ScreenCaptureService` (`zere/tools/windows/screen_capture_service.py`) написан, но не подключён ни к одному обработчику. Команды «сделай скриншот», «что на экране», «прочитай текст с экрана» не работают (скриншот браузерной страницы умеет только Playwright MCP).

### 6.5 Поиск по своим файлам (RAG)

Конспектор умеет читать файлы и резать их на части («Ставка 1»), но векторного слоя и команды «найди в моих файлах…» нет. Это самая заметная функциональная дыра относительно собственных планов.

### 6.6 Паритет двух редакций

C#-панель — 27 маршрутов, Python — 32. В C# отсутствуют `/api/update*` и `/api/plugins/mcp*` (обновление и MCP-плагины). Python, в свою очередь, не имеет трея. Выбор «ведущей редакции» в README/AGENTS.md так и не зафиксирован — рекомендация отчёта 2026-10-21 не выполнена.
