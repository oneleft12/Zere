# Отчёт: анализ проекта ZERE

**Дата:** 2026-09-27
**Ветка:** `python-port` (HEAD `9faa8a5`, синхронизирована с `origin/python-port`)
**Метод:** три параллельных код-ревью (ядро, инструменты/безопасность, голос/память/гигиена) с проверкой каждого факта чтением файлов, плюс собственные проверки: `python3 -m compileall`, `scripts/check_port.py`, интроспекция `zere.db`, `git ls-files`, grep-сканы. Окружение — Linux; `dotnet` недоступен, сборка C# в этот раз не выполнялась.

## 1. Резюме

**ZERE** — локальный AI-ассистент для Windows с двумя параллельными реализациями: C#-решение (.NET 10, 6 проектов) и Python-порт (`zere/`, 125 модулей), зеркальный по структуре. Проект архитектурно дисциплинирован: слойность, DI, единый конвейер из 9 обработчиков, параметризованный SQL, продуманные фолбэки голосового стека, богатая документация. Python-порт местами устойчивее исходника (откат конфига к дефолтам, `paths.py` не зависит от CWD, LRU-кэш Ollama, таймауты).

Однако **системные проблемы предыдущего аудита (2026-09-23) не исправлены — ни один пункт P0 не закрыт**:

1. **История диалогов не сохраняется вовсе** (обе реализации) — README-фича не работает, контекст для LLM всегда пуст.
2. **Path traversal в файловых операциях** — `..` и абсолютные пути обходят «только рабочий стол».
3. **Опасные действия без реального подтверждения** — kill процессов и удаление файлов мгновенны; подтверждение выключения — голое «да» без TTL, матчинг ловит отрицания («не выключай компьютер»).

Плюс собственные находки этого раунда: системный промпт удваивается при отправке в Ollama, стиль личности не персистится после рестарта, Python-обнаружение внешних плагинов заведомо нерабочее (сравнение строки с объектом модуля), два независимых WhisperService держат двойную загрузку модели, ошибка микрофона вне `try/catch` роняет приложение, ветка `main` (дефолтная на GitHub) отстаёт на 11 коммитов и не содержит Python-порт.

**Оценка:** архитектура — 8/10; реализация деталей и безопасность — 5/10; тестирование и CI — 1/10; документация — 8/10. Готовность к цели «автономный ассистент» сдерживается P0 (история, пути, подтверждения) и отсутствием тестовой защиты любых исправлений.

## 3. Архитектура (кратко)

**C#:** `ZERE.App` (консольный цикл) → `ZereEngine.ProcessAsync` → `HandlerPipeline` (фиксированный массив 9 обработчиков, `ServiceRegistration.cs:75-91`) → `AIHandler` → `OllamaClient` (`/api/generate`). Память — SQLite (`ZERE.Memory`), инструменты — `ZERE.Tools`, голос — `ZERE.Voice` (Whisper STT, Piper/PocketTTS TTS, wake word с VAD).

**Python-порт:** полное зеркало (`zere/ai`, `core`, `memory`, `tools`, `voice`), порядок конвейера идентичен (`zere/core/services.py:269-284`), соответствие отслеживается `scripts/check_port.py`.

**Замечания:**
- Порядок конвейера создаёт конфликты перехвата (см. P1-1): `WindowsHandler` (5-й) раньше `FileHandler` (6-й), `MemoryQueryHandler` (2-й) перехватывает все «что такое …» до LLM.
- Плагинная система: личности (5 стилей) работают; `ICommandHandlerPlugin` загружается, но **в конвейер не подключается** (см. P1-4).
- Две реализации разошлись по конфигурации и данным (см. P1-5): C# не читает `voiceVolume`, Python не читает `ttsEngine`/`voiceReferencePath` и не имеет PocketTTS; C# хранит БД в `%LOCALAPPDATA%`, Python — в корне репозитория.

## 4. Сильные стороны

1. **Чистая слойность** — зависимости направлены внутрь, порядок конвейера задан в одном месте, Python-порт 1:1 с комментариями соответствия C#-строкам.
2. **Параметризованный SQL** во всех репозиториях — SQL-инъекций не найдено.
3. **Отказоустойчивость голоса:** персистентный piper с ресинхронизацией по RIFF, попредложенное стриминг, реконнект Whisper/Piper, откат pocket→piper, таймауты, `errors.log` — «Фаза 1 Стабильность» в основном закрыта.
4. **`WakeWordDetector`** — энергетический VAD + кольцевой буфер + нечёткое сравнение Левенштейна.
5. **Python-порт местами устойчивее C#:** fallback конфига при битом JSON, LRU-кэш Ollama, таймаут транскрибации, `paths.py` не зависит от рабочей директории, скриншот через `mss` вместо PowerShell (инъекция исправлена).
6. **Документация** (`ARCHITECTURE`, `ROADMAP`, `PYTHON_PORT_SPEC`, research-документы) — заметно выше среднего для личного проекта.
7. **Гигиена секретов:** `.gitignore` покрывает ключи/модели, сканером секретов в треке ничего не найдено.

## 5. Критические находки (P0) — не исправлены с аудита 2026-09-23

### P0-1. История диалогов никогда не сохраняется (обе реализации)
- `ConversationRepository.Save` / `conversation_repository.save` **не вызывается нигде** в активном коде (проверено grep: только `backups/v1.3–v1.5/ZereEngine.cs`); engine выполняет только извлечение фактов и прогон конвейера (`ZERE.Core/ZereEngine.cs:21-36`, `zere/core/engine.py:26-37`).
- Следствия: «покажи историю» всегда отвечает «История пуста»; `ContextBuilder.BuildHistory` читает пустую таблицу → многоходового контекста нет; `zere.db` подтверждён пустым (0 строк).
- **Латентный баг после исправления:** `GetLast` сортирует `ORDER BY Id DESC`, `ContextBuilder` не разворачивает список (`ConversationRepository.cs:60-62` + `ContextBuilder.cs:41-46`) → контекст уйдёт в обратной хронологии.
- **Рекомендация:** `Save(request, answer)` в оба engine + `.Reverse()` в `BuildHistory` + тест на round-trip.

### P0-2. Path traversal в файловых операциях
- `FileManager.CreateFolder/CreateFile` (`ZERE.Tools/Files/FileManager.cs:21,33`, `zere/tools/files/file_manager.py:21,31`) склеивают имя из реплики пользователя с рабочим столом без нормализации: `..` и абсолютный путь полностью обходят ограничение; `create_file` дополнительно не перезаписывает существующие (проверка `is_file`), но C#-вариант перезаписывает.
- `DeleteFile` удаляет первое совпадение имени без подтверждения, permanent (не в корзину).
- **Рекомендация:** `Path.GetFullPath`/`resolve()` + проверка, что результат внутри desktop; запрет абсолютных путей и `..`; подтверждение удаления.

### P0-3. Опасные действия: подтверждение формальное, отрицания не работают
- **Kill процессов** — без всякого подтверждения, убивает **все** совпадения вместе с дочерними (`ProcessHandler.cs:74-78`, `ProcessService.cs:50` `Kill(true)`); пустые `catch` + `return true` → «Процесс X закрыт» может врать (`ProcessService.cs:52-57`).
- **Power-действия:** подтверждение — любое одиночное слово «да/подтверди/выполни/сделай» (`WindowsHandler.cs:81`), pending-действие в `SafeActionManager` **без TTL** — «да», сказанное спустя час, выполнит `shutdown /s /t 0`.
- **Ложные срабатывания:** `Contains("перезагрузка")`/`Contains("выключай компьютер")` без учёта отрицаний → «не выключай компьютер» запрашивает подтверждение выключения; «после перезагрузки файлы сохранятся?» → подтверждение рестарта.
- **Рекомендация:** TTL 30–60 с, привязка к последнему запросу, фраза-подтверждение («подтверди выключение»), откат при «не/нет», denylist системных процессов, честный результат kill.

## 6. Важные находки (P1)

### P1-1. Перехват команд раньше AIHandler и раньше FileHandler
- `MemoryQueryHandler.CanHandle`: `StartsWith("что такое ")` / `"кто такой "` (`MemoryQueryHandler.cs:23-25`, `memory_query_handler.py:22-24`) — при пустой памяти отвечает «Я пока не знаю ответ.» (`:85`) → «что такое гравитация» **никогда не доходит до LLM**.
- `WindowsHandler`: `StartsWith("найди ")` (`WindowsHandler.cs:25`, `windows_handler.py:26`) идёт раньше `FileHandler` (`ServiceRegistration.cs:83-84`) → «найди файл X» уходит в поиск приложений, файловый поиск недостижим.
- `FileCommandRouter` возвращает `DeleteLastFile` для «удали его», но кейса в `FileHandler` нет → «Команда файлов не распознана» (`FileHandler.cs:55-74`).
- `VolumeHandler`/`ProcessHandler`: `Contains("тише")`, `StartsWith("закрой ")` перехватывают «говори тише», «закрой дверь».
- **Рекомендация:** fallthrough к LLM при отсутствии совпадения, точные префиксы, реализовать или удалить `DeleteLastFile`.

### P1-2. Удвоение системного промпта и плоский prompt
`PromptBuilder` уже вкладывает system prompt в prompt, затем `AIHandler` склеивает `"{systemPrompt}\n\nПользователь: {prompt}"` (`AIHandler.cs:33-40`, `OllamaClient.cs:43-45`; то же в Python) — промпт удваивается, память/история подписаны как «Пользователь», поле `system` API Ollama не используется. **Рекомендация:** `/api/chat` с ролями, system — только через поле `system`.

### P1-3. Плагины-обработчики мертвы; Python-загрузка внешних плагинов сломана
- `CommandHandlers` объявлены (`PluginManager.cs:16`), но массив конвейера фиксирован при DI-регистрации — чтения `CommandHandlers` нигде нет (проверено grep). Документация утверждает обратное (`docs/ARCHITECTURE.md:106`).
- **Проверено повторно:** `load_plugin` (`plugin_manager.py:131-137`) отбирает классы по `obj.__module__ == module` — строка сравнивается с объектом модуля → **всегда ложно**, ни один `plugins/*.py` не загрузится никогда.
- Смена стиля личности не персистится: `SettingsMenu` пишет только `ActivePersonalityId`, `ActivePersonalityStyle` не сохраняется (`SettingsMenu.cs:104-107`) → после рестарта стиль сбрасывается.

### P1-4. Конфигурационный дрейф между реализациями
- C# **не читает `voiceVolume`** (`ZereConfig.cs` — поля нет, `VoiceConfig.cs:24` — всегда 1.0); Python **не читает `ttsEngine`/`voiceReferencePath`** и не имеет PocketTTS/«записать голос» вовсе (grep: 0 совпадений) — при `ttsEngine: pocket` в `config/config.json` Python-ветка молча работает на Piper.
- Мёртвые ключи в обеих: `autoMemory`, `debugMode`, `logLevel` объявлены, не читаются; `MemoryExtractor` игнорирует `AutoMemory`.
- C#: `Load()` вызывается дважды (`Program.cs:12` + `ServiceRegistration.cs:25`) → два разных инстанса конфига; путь через `Directory.GetCurrentDirectory()` — запуск вне корня создаёт пустой конфиг; битый JSON валит старт (Python откатывается к дефолтам).
- Python `piper_service.py:116-123` хардкодит `length_scale 1.15`/`sentence_silence 0.4` вместо конфига (C#: 0.2, настраиваемо).
- Разные пути БД: C# — `%LOCALAPPDATA%\ZERE`, Python — корень репо → реализации не делят память.

### P1-5. Надёжность голосового ввода
- Ошибка микрофона **вне** try/catch: `Program.cs:156,211`, `AudioRecorder.cs:59`, `voice_manager.py:97` + `audio_recorder.py:56` → необработанное исключение завершает приложение (в Python та же дыра несмотря на порт).
- Два независимых `WhisperService` (`VoiceManager.cs:13` и `WakeWordDetector.cs:16`) → двойная загрузка модели (~1.5 ГБ RAM).
- Откат pocket→piper работает только при `Initialize`; после смерти TTS-сервера каждый ответ уходит в текст (`VoiceManager.cs:74-86`), вопреки обещанию AGENTS.md об откате «при сбоях».

### P1-6. Небезопасный установщик зависимостей
- Распаковка Piper: путь `glob("piper*.zip")` из Downloads/Desktop вставляется в single-quoted PowerShell (`DependencyChecker.cs:662-670`, `dependency_checker.py:569-579`) — имя с `'` → произвольный код; архив не проверяется по SHA-256; любой `piper*.zip` копируется в проект без подтверждения и позже исполняется.
- Тот же паттерн: интерполяция в `cmd.exe /c {command}` (`DependencyChecker.cs:198`), `$"ollama pull {_config.Model}"` (`:359`) без валидации имени модели.
- `RegistryScanner` не фильтрует score 0 (`RegistryScanner.cs:122-127`) → «открой X» может запустить деинсталлятор; `LocalAppDataScanner` берёт самый короткий `.exe` и своим Priority=100 перетирает записи StartMenu/Registry.
- **Рекомендация:** распаковка через `zipfile`/`System.IO.Compression` без shell, SHA-256 фиксированного релиза, `Where(score > 0)`, уважение приоритета сканеров.

### P1-7. Инженерная гигиена
- **0 тестов, 0 CI** — любые исправления P0 нечем подстраховать; ROADMAP 5.4 не закрыт.
- **Нет LICENSE** при заявленном MIT (`README.md:77`).
- **`requirements.txt`:** `numpy` (импортируется в 5 файлах `zere/voice/audio/*`) не объявлен, `comtypes` объявлен, но нигде не используется; только нижние границы, lock-файла нет.
- **Рантайм-артефакты в git:** `zere.db`, `processed_output_*.wav` (3 шт., ≈3.7 МБ), `voice/*.wav|mp3` — биометрия голоса и БД в истории; `.gitignore` покрывает только `voice/reference.wav`.
- **Дрейф веток:** дефолтная `origin/HEAD → main` отстаёт на 11 коммитов и не содержит Python-порт — посетитель репозитория видит устаревшую C#-версию.
- **README/AGENTS-дрейф:** заявлено 6 стилей личности, фактически доступно 5 (Custom исключён из `GetAvailableStyles()`); `AGENTS.md` перечисляет `System/`-сервисы как активные, хотя они не в DI; `AGENTS.md` описывает Python-плагины как рабочие (см. P1-3).

**Ближайший спринт (P1):**

5. `/api/chat` с ролями, убрать двойной system prompt (P1-2).

7. Унифицировать конфиг C#/Python, убрать мёртвые ключи, определиться со статусом PocketTTS в Python (P1-4).
