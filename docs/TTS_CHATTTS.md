# TTS на ChatTTS (2Noise/ChatTTS)

**Статус:** текущий движок синтеза речи в ZERE; заменил Piper.
**Код:** `zere/voice/chattts/chattts_manager.py`, `zere/voice/chattts/chattts_service.py` (Python-редакция),
`ZERE.Voice/ChatTts/ChatTtsService.cs` (C#-редакция), сайдкар `tools/zere_chattts_server.py`.
**Тесты:** `tests/test_chattts.py`.

---

## 1. Назначение и место в архитектуре

ChatTTS — нейросетевой синтез речи (нейросеть-трансформер на 24 кГц). Это замена
прежнего Piper, но **без изменения архитектуры голосового слоя**.

**Почему контракт PiperService сохранён.** Доступ к TTS во всём проекте идёт через
один набор членов, поэтому новый движок реализует ровно тот же контракт:

| Редакция | Контракт (идентичен прежнему `PiperService`) |
|---|---|
| Python | `is_loaded`, `current_voice`, `initialize()`, `speak()`, `set_voice()`, `set_inference_params()`, `get_available_voices()`, `close()` |
| C# | `IsLoaded`, `CurrentVoice`, `Initialize`, `SynthesizeStreamAsync` (попредложенно, отдаёт путь к WAV), `SetInferenceParams`, `SetVoice`, `GetAvailableVoices`, `Dispose` |

Благодаря этому `VoiceManager` и остальные модули править не пришлось: TTS-движок
подменяется целиком, а роутинг (`ttsEngine`) и отказы остались на прежнем месте.

**C# ↔ сайдкар.** C# не может импортировать Python-библиотеку, поэтому тяжёлая часть
вынесена в отдельный HTTP-процесс — тот же приём, что и у PocketTTS. Сайдкар
`tools/zere_chattts_server.py` поднимает сам C#-клиент (`ChatTtsService.StartServer`),
переиспользует `ChatTTSManager` из `zere/voice/chattts/` (одна реализация инициализации
на обе редакции) и отдаёт синтез по HTTP. Питоновская редакция работает с ChatTTS
in-process, без сайдкара.

**Роутинг.** `ttsEngine` принимает `"pocket"` | `"chattts"` (в `config/config.json`
стоит `"chattts"`). Откат при сбое PocketTTS идёт на ChatTTS (раньше — на Piper);
`VoiceManager.IsTtsAvailable` = PocketTTS **или** ChatTTS.

## 2. Ленивая загрузка (два слоя)

Модель ChatTTS тяжёлая (torch + веса, ~2–3 ГБ), поэтому её загрузка отложена до
первого реального синтеза — на старте ZERE TTS не платит ни временем, ни памятью.

| Слой | Что проверяется в `Initialize` | Когда появляются модель и веса |
|---|---|---|
| C# (`ChatTtsService.Initialize`) | только инструментарий: есть ли `tools/uv.exe` и `tools/zere_chattts_server.py` | первый `SynthesizeStreamAsync`: `EnsureServerAsync` поднимает сайдкар, ждёт `/health` = `ready` (таймаут первой загрузки — 10 минут) |
| Python (`ChatTtsService.initialize`) | `ChatTTSManager.availability()` — `importlib.util.find_spec` по `ChatTTS`/`torch`/`soundfile`, **без импорта** | первый `speak()`: `ChatTTSManager.load_model()` создаёт `ChatTTS.Chat()` и грузит веса |

Дополнительно: `availability()` намеренно не импортирует ChatTTS (иначе тянулась бы
вся связка torch/numba), а `load_model()` идемпотентен — модель ровно одна на процесс.

**Поведение при недоступности.** Если ChatTTS нет в окружении (или инструментарий не
найден), `Initialize` возвращает `false`, а `speak()` отдаёт пустой результат — цикл
ZERE продолжает работать в текстовом режиме, без исключений. В C#-редакции после двух
неудачных попыток поднять сервер TTS выключается до перезапуска ZERE (тот же исход,
что раньше был у Piper без `piper.exe`).

**Как это проверено** (`tests/test_chattts.py`): `test_initialize_does_not_load_model`
(адаптер не создаёт модель), `test_model_is_lazy_and_loads_once` (первый синтез — одна
загрузка, второй переиспользует), `test_load_model_is_idempotent`,
`test_close_releases_model`, `test_availability_does_not_import_heavy_modules`.

## 3. Эталонная инициализация и параметры инференса

Инициализация ровно по эталону ChatTTS:

```python
chat = ChatTTS.Chat()
chat.load(compile=False)          # compile=False — стабильность первого запуска
```

`compile=False` выбран сознательно: `torch.compile` может падать на неподдерживаемом
железе, а первый запуск важнее потенциального ускорения.

Параметры инференса — через `InferCodeParams`:

| Параметр | Значение | Зачем |
|---|---|---|
| `temperature` | `0.3` | меньше вариативности, стабильный голос |
| `top_P` | `0.7` | отсечение «мусорных» токенов |
| `top_K` | `20` | то же, по числу кандидатов |

Частота дискретизации ChatTTS — **24 кГц** (у Piper было 22.05 кГц). WAV пишется
через `soundfile` (`sf.write(path, wav.squeeze(), 24000)`); ресемплинг под конкретное
устройство вывода делает обычный тракт (`AudioProcessor` / `ResolveOutputSampleRate`).

## 4. Профили голоса

У ChatTTS нет именованных голосов: он умеет `sample_random_speaker()`. Поэтому
«профиль голоса» ZERE — это **детерминированное зерно**: имя профиля → `crc32` →
`torch.manual_seed` → эмбеддинг говорящего. Один профиль всегда звучит одинаково,
разные профили — по-разному. Эмбеддинг кэшируется, перезагрузка модели при смене
голоса не нужна.

| Профиль | Назначение |
|---|---|
| `zere-standard` | по умолчанию |
| `zere-warm` | стиль личности **Friendly** |
| `zere-strict` | **Formal** |
| `zere-ironic` | **Sarcastic** |
| `zere-business` | **Professional** |
| `zere-casual` | **Casual** |

Пользовательские эмбеддинги можно положить в `ZERE.Voice/ChatTts/voices/*.pt` — они
добавляются к списку профилей (`spk_smp`); папка gitignored.

## 5. Темп речи и паузы

- **Темп.** `speechSpeed` (`VoiceConfig`, по умолчанию `1.15`) имеет семантику
  Piper `--length_scale`: `1.0` — норма, больше — медленнее. У ChatTTS темп задаётся
  токеном `[speed_N]` (шкала `1…9`), поэтому шкала дискретная: `speed = round(5 / length_scale)`
  с зажимом в `1…9`. Так `1.0 → [speed_5]` (нейтрально), `1.15 → [speed_4]`. Маппинг
  живёт в `ChatTTSManager.set_inference_params` и общий для обеих редакций, чтобы темп
  не разъезжался; в сайдкаре `speed` — это тот же `length_scale`.
- **Пауза.** `sentenceSilence` (`VoiceConfig`, по умолчанию `0.2` с) — тишина,
  дописываемая после **каждого** предложения (аналог Piper `--sentence_silence`).
  Текст режется на предложения и синтезируется попредложенно: первое предложение
  начинает играть, пока синтезируется следующее.

Параметры приходят на каждый запрос, поэтому смена темпа/паузы (в отличие от Piper)
**не перезапускает процесс** и не перезагружает модель.

## 6. Схема данных сайдкара (HTTP)

Сайдкар слушает `127.0.0.1:8472` (порт по умолчанию, `--port`).

| Запрос | Ответ |
|---|---|
| `GET /health` | `{"status": "loading"\|"ready"\|"error", "detail": str, "sample_rate": 24000, "voice": str, "voices": [...]}` |
| `GET /voices` | `{"voices": [...]}` |
| `POST /tts` | тело: `{"text": "...", "voice": "zere-warm", "speed": 1.15, "silence": 0.2}` → `application/octet-stream`: **PCM s16le, моно, 24 кГц**, заголовок `X-Sample-Rate: 24000` |

- PCM отдаётся порциями (~0.2 с, 4800 сэмплов) по мере инференса; соединение
  закрывается по концу потока (`Connection: close`, без `Content-Length`).
- Модель грузится в фоне после старта сервера, поэтому `/health` успевает ответить
  `loading`, а клиент ждёт `ready` вместо таймаута на первом запросе.
- C#-клиент заворачивает полученный PCM в полноценный WAV (RIFF, 16 бит, моно) и
  дальше отдаёт файл в обычный тракт: DSP-обработка + воспроизведение.
- Цифры в тексте раскрываются в слова через `num2words` (ChatTTS обучен на тексте,
  а не на цифрах); модуль опционален — без него текст уходит как есть.

## 7. Запуск сайдкара через uv

C#-клиент запускает сайдкар так:

```
tools/uv.exe run --python 3.12 --with ChatTTS --with soundfile --with num2words \
    python tools/zere_chattts_server.py --port 8472 --voice <профиль>
```

`--python 3.12` здесь принципиален: у `torch`/`numba` нет сборок под Python 3.13+,
а `uv` скачивает совместимый интерпретатор сам и **не трогает системный Python** —
установка ZERE не зависит от его версии.

## 8. Зависимости и установка

- `requirements.txt`: `ChatTTS>=0.2.1; python_version < "3.13"` и `soundfile>=0.12`.
  Маркер версии обязателен: на Python 3.13+ пакет не ставится, и pip не должен
  ломать установку остальных зависимостей.
- Установщик (`installer/install.ps1`) вместо артефактов Piper скачивает **`uv`**
  (релиз 0.12.23, SHA-256 `75d05de6762778c31ee183398de7dd15093fad0ed90b1f236d8205ea5ec00c90`,
  размер 18043715 байт) и распаковывает в `tools/`. Артефакты `Piper`, `PiperVoice`,
  `PiperVoiceJs` из установщика удалены, из `uninstall.ps1` — бинарники Piper.
- **Веса ChatTTS установщик не качает**: `uv` приносит их сам при первом синтезе
  (~2–3 ГБ вместе с torch) и кэширует.
- `.gitignore`: рантайм-данные движка — `ZERE.Voice/ChatTts/output_*.wav`,
  `processed_*.wav`, `voices/`.

## 9. Ограничения и риски

1. **Русский язык не гарантирован.** ChatTTS официально поддерживает китайский и
   английский; качество **русской** речи не гарантировано и требует проверки на слух.
   Это осознанный компромисс ради «человечности» голоса.
2. **Лицензия весов — CC BY-NC 4.0** (только некоммерческое использование). Для
   коммерческого релиза ZERE это **блокер**, требующий юридической проверки
   (см. `docs/COMMERCIAL_RELEASE_PLAN.md`).
3. **Латентность и размер.** Первый синтез скачивает ~2–3 ГБ (torch) и грузит модель;
   инференс на CPU медленный (RTF заметно больше 1). Поэтому задержка первого звука
   у ChatTTS **выше**, чем была у Piper (~40 мс). PocketTTS остаётся основным
   движком, ChatTTS — откат/офлайн-вариант **без клонирования** голоса.
4. **Python 3.13+.** Пакет ChatTTS не ставится на Python 3.13+ (маркер в
   `requirements.txt`) → Python-редакция уходит в текстовый режим **без ошибок**.
   Для C#-редакции это решено через `uv` с `--python 3.12`.

## 10. Тесты

`tests/test_chattts.py` (33 теста; запуск — `python3 tests/test_chattts.py` или
`pytest tests/ -q`). Тяжёлые зависимости не нужны: `ChatTTS`, `numpy`, `soundfile`
подменяются фейками через `sys.modules` — это заодно доказывает, что ленивость
настоящая (импорт внутри методов, а не на уровне модуля). Проверяется:

- **ленивая загрузка** — `initialize()` не создаёт модель; первый синтез грузит ровно
  один раз; повторный `load_model()` идемпотентен; `close()` выгружает модель;
  `availability()` не импортирует ChatTTS;
- **контракт, идентичный PiperService** — набор членов адаптера, `is_loaded=false` до
  `initialize`, недоступность движка → `speak()` возвращает `""`;
- **эталонные параметры** — `temperature 0.3` / `top_P 0.7` / `top_K 20` доходят до
  `InferCodeParams`; WAV пишется на 24000 Гц;
- **профили голоса** — детерминированное зерно по `crc32` (одинаковое имя → одинаковое
  зерно, разное → разное), кэш эмбеддинга, список профилей, смена без перезагрузки;
- **попредложенный синтез** — текст режется на предложения, после каждого дописана
  тишина `sentenceSilence`;
- **маппинг темпа** — `1.15 → [speed_4]`, `1.0 → [speed_5]`, зажим в шкалу `1…9`;
- **контракт сайдкара** — `prepare()` выравнивает текст, `speed` приходит как
  `length_scale` и переводится в `[speed_N]`, объявлены PCM s16le / 24 кГц /
  `X-Sample-Rate` / эндпоинты `/health` и `/tts`.

## 11. Откат на Piper

Если ChatTTS не подойдёт (русское качество, лицензия, латентность), движок
возвращается так:

1. `git revert` коммита, которым выполнена замена Piper → ChatTTS (вся замена —
   один коммит). Это вернёт `ZERE.Voice/Piper/PiperService.cs`,
   `zere/voice/piper/piper_service.py`, `paths.piper_dir()`, роутинг `pocket→piper`
   и прежний набор артефактов установщика.
2. Убедиться, что в `config/config.json` снова стоит приемлемое значение `ttsEngine`
   (`"pocket"` или `"piper"`).
3. **Важно:** текущий установщик больше **не** скачивает Piper-артефакты
   (`piper_windows_amd64.zip`, голос `ru_RU-ruslan-medium.onnx` + `.onnx.json`),
   а `uninstall.ps1` больше не удаляет бинарники Piper. После отката эти файлы
   придётся положить в `ZERE.Voice/Piper/` вручную (SHA-256 прежних артефактов
   сохранены в истории `docs/INSTALL.md`).
