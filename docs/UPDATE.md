# Обновление ZERE из GitHub

ZERE обновляется **из своего git-репозитория**: приложение проверяет ветку на
GitHub и по кнопке делает fast-forward (`git pull --ff-only`). Никаких
сред слияния, перезаписи конфигов или удаления данных: обновляется только код.

Реализация — `zere/core/update/updater.py` (`UpdateService`).

## Как это работает

```
панель «Обновления» (/update)                    GitHub (origin)
        │                                              │
        │ 1. автопроверка при старте панели             │
        │    или кнопка «Проверить обновления»          │
        ├────────── git fetch ─────────────────────────►│
        │           +refs/heads/<ветка>:refs/remotes/origin/<ветка>
        │◄───────── новые коммиты ──────────────────────┤
        │ 2. сравнение HEAD ↔ origin/<ветка>            │
        │    (behind / ahead / список коммитов)         │
        │ 3. кнопка «Обновить сейчас»                   │
        ├────────── git pull --ff-only ────────────────►│
        │ 4. pip install -r requirements.txt,           │
        │    если файл изменился                        │
        │ 5. «нужен перезапуск» — запущенный процесс    │
        │    всё ещё держит старый код в памяти         │
```

Шаги 1–2 — сеть. Всё остальное локально. `GET /api/update` **не ходит в
сеть**: он отдаёт последнее известное состояние (автопроверка при старте или
последний `POST /api/update/check`).

## Что делают кнопки панели

| Кнопка | Что происходит |
|---|---|
| Автопроверка при старте | Фоновый `git fetch` после запуска панели; строка `[Обновление] Доступно N коммитов…` в консоли и отметка `⬆ обновление: N` в статус-строке панели |
| «Проверить обновления» | `POST /api/update/check` — `git fetch` + пересчёт состояния |
| «Обновить сейчас» | `POST /api/update/apply` — `git pull --ff-only`, затем зависимости |

Кнопка «Обновить сейчас» неактивна, если обновление нельзя применить
безопасно: причина видна в карточке «Состояние» (`blockedReason`).

## Отказы вместо «тихого» риска

`git pull` применяется только как fast-forward и только в чистой рабочей
копии. Иначе операция отменяется, ничего не трогая:

| Причина (`blockedReason`) | Что это значит | Что делать |
|---|---|---|
| `есть незакоммиченные изменения` | В репозитории есть локальные правки отслеживаемых файлов | Зафиксировать (`git stash` / `git commit`) и повторить |
| `ветки разошлись` | Локальная ветка ушла вперёд origin | Разобрать вручную: `git log --oneline origin/<ветка>..HEAD` |
| `git fetch не удался` | Нет сети, нет доступа к репозиторию, ключ просит пароль | Проверить `git fetch` в терминале от того же пользователя |
| `нет git-репозитория` | Установка без `.git` (архив, Setup.exe) | Обновление только через git-копию репозитория |
| `нет git` | `git` не найден в `PATH` | Установить [Git для Windows](https://git-scm.com/download/win) |

Приватный репозиторий читается теми же ключами, что и обычный `git`:
проверка идёт без интерактива (`GIT_TERMINAL_PROMPT=0`, SSH `BatchMode=yes`),
поэтому парольная фраза на ключе или запрос логина приводят к понятной
ошибке, а не к «зависшей» панели. Подходит ключ без парольной фразы либо
credential helper git.

## Что не перезаписывается

Обновляется только то, что лежит в git. Личные данные и артефакты установки
игнорируются или не входят в репозиторий:

- `config/` — `config.json`, `plugins.json`, `panel.token`;
- `zere.db` — память и история разговоров;
- `logs/`, `backups/`;
- `voice/Models/` — GigaAM, Whisper `ggml-base.bin`;
- `tools/xVibePocketTTS/`, `.venv/`, `node_modules/`.

Панель (`panel/dist`) собирается в git, поэтому после `pull` интерфейс уже
новый — пересборка `npm run build` не нужна. Зависимости Python ставятся
автоматически, если в подтянутых коммитах менялся `requirements.txt`
(поле `dependencies` в ответе: `updated` / `skipped` / `failed`).

## Перезапуск

После успешного обновления панель показывает «нужен перезапуск»: запущенный
процесс продолжает исполнять старый код, потому что модули уже загружены.
Закройте ZERE и запустите снова (ярлык «ZERE»). Панель процесс не
перезапускает намеренно: перезапуск убил бы голосовой цикл и историю сессии.

## Из консоли (если панель не поднимается)

```bash
python -m zere.core.update            # состояние из кэша (без сети)
python -m zere.core.update --check    # git fetch + сравнение с origin
python -m zere.core.update --apply    # git pull --ff-only + зависимости
python -m zere.core.update --apply --no-deps   # без pip install
```

Обычный git тоже работает: `git fetch && git pull --ff-only`, затем
`pip install -r requirements.txt` и перезапуск.

## Откат

История локальная, поэтому откат — обычные средства git:

```bash
git log --oneline -5                  # найти прежний коммит
git reset --hard <hash>               # вернуть код
```

## API

Контракт — `docs/api/openapi.yaml` (схемы `UpdateStatus`, `UpdateOutcome`,
`UpdateApplyRequest`):

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/update` | Состояние из кэша (без сети) |
| `POST` | `/api/update/check` | `git fetch` + сравнение с `origin/<ветка>` |
| `POST` | `/api/update/apply` | `git pull --ff-only` (+ зависимости). Тело: `{"installDependencies": true}`; `409 UPDATE_BUSY`, если операция уже идёт |
